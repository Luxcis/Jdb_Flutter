# 启动域名引导设计

## 目标

每次应用冷启动时先显示独立加载页，并且只使用固定主域
`https://jdforrepam.com` 调用 `/api/v1/startup`。获取并应用备用域名成功后，
通过 `router.go('/home')` 进入首页；此后的全部业务接口使用本次启动返回的
备用域名。

启动请求失败、响应缺少可用域名或域名数据无法解密时，不进入首页。加载页
显示错误信息和重试按钮，用户重试成功后继续正常启动流程。

## 范围

- 调整应用初始路由和启动页状态。
- 将启动接口请求与业务接口请求使用的域名策略分离。
- 沿用现有 `DomainManager`、备用域名解密和业务域名轮转能力。
- 不新增第三方依赖，不修改首页业务内容，不实现自动定时重试。

## 方案

采用独立的启动请求客户端。启动客户端使用固定主域，并仅安装启动接口所需
的签名、Debug 响应日志和业务响应解析拦截器；它不读取持久化业务域名，也不
安装认证或域名切换拦截器。

不复用业务 `ApiClient` 临时切换域名，因为业务客户端启动时会恢复上次持久化
的域名，并包含域名轮转状态。将两类请求分开可以保证每次启动请求的目标域名
始终确定，同时避免失败重试意外切换到历史备用域名。

## 组件职责

### 启动请求客户端

- `baseUrl` 固定为 `AppConstants.fallbackBaseUrl`。
- 请求路径固定使用 `Endpoints.startup`。
- 保留现有启动参数，并补齐 OpenAPI 标记为必填的 `last_ad_id` 参数。
- 对成功响应执行现有响应信封解包。
- 不持有登录状态，不因 HTTP 608 或网络错误轮转域名。
- 支持测试注入 `HttpClientAdapter`，以验证实际请求主机。

### `StartupProvider`

Provider 维护互斥的加载、失败和成功状态：

- `load()` 发起一次启动请求，并在请求期间进入加载状态。
- 成功响应必须包含可解密且 `apiDomains` 非空的备用域名数据。
- 成功后调用 `DomainManager.applyStartup()`，再同步业务 `ApiClient` 的
  `baseUrl`，确保后续请求立即使用返回列表的首个域名。
- 仅在域名持久化与业务客户端同步全部完成后进入成功状态。
- 任一步骤失败都进入失败状态，并提供稳定的中文错误提示。
- `retry()` 复用同一流程；加载期间忽略重复触发。
- Provider 不直接依赖路由，导航由页面根据成功结果执行。

无效或空域名数据不再回退为 `jdforrepam.com` 并继续进入首页，因为固定主域
只负责发现备用域名，不能作为本次启动成功后的业务域名。

### 启动页与路由

- 新增 `AppRoutes.startup`，生产 `GoRouter` 的默认初始地址改为
  `/startup`。
- 启动页首次挂载后触发 `StartupProvider.load()`，避免在 `build()` 中重复
  发起网络请求。
- 加载状态使用纯主题背景和居中的 `CircularProgressIndicator`，不显示首页
  或底部导航。
- 失败状态显示“启动失败，请检查网络后重试”和“重试”按钮。
- 点击重试后恢复加载状态，按钮不可重复触发。
- 成功后由启动页调用 `context.go(AppRoutes.home)`；使用 `go` 替换启动页，
  系统返回操作不会回到加载页。
- 测试路由仍允许显式指定初始地址，避免破坏各功能页面的独立 Widget 测试。

## 启动流程

1. `main()` 创建持久化、主题、认证、设置、业务 `ApiClient` 和
   `StartupProvider`，但不再 fire-and-forget 调用启动接口。
2. `MyApp` 创建默认地址为 `/startup` 的路由。
3. 启动页触发固定主域的启动请求。
4. Provider 解密并校验备用域名列表。
5. `DomainManager` 写入域名列表、当前域名和图片端点。
6. 业务 `ApiClient` 切换至返回列表的首个域名。
7. 启动页使用 `router.go` 前往 `/home`。
8. 后续业务请求继续使用现有业务客户端和域名轮转拦截器。

## 错误处理

- 网络超时、连接失败、HTTP 错误、业务失败、解密失败、空域名列表和持久化
  失败均视为启动失败。
- 失败时保留在启动页，不自动进入首页，也不使用上次保存的域名绕过本次启动。
- 页面展示统一提示，不直接暴露 Dio、服务端或解密异常细节。
- 每次点击重试都重新访问固定主域；成功后才清除页面错误状态并导航。

## 测试与验收

按照 TDD 顺序增加以下回归覆盖：

1. 启动请求即使存在已保存的备用域名，实际请求主机仍是
   `jdforrepam.com`。
2. 有效响应会更新 `DomainManager`、持久化首个备用域名并同步业务
   `ApiClient.baseUrl`。
3. 空、缺失或无法解密的域名数据会进入失败状态，不标记启动成功。
4. 加载页首次显示时只发起一次请求，并展示加载指示器。
5. 请求失败后页面展示错误提示和重试按钮，且不会进入首页。
6. 点击重试成功后使用 `router.go('/home')`，启动页不保留在返回栈中。
7. 进入首页后发起的业务请求使用本次启动获得的首个备用域名。

验证顺序为目标单元测试、目标 Widget 测试、相关网络回归测试、静态分析，
最后再运行完整测试套件并如实记录既有无关失败。
