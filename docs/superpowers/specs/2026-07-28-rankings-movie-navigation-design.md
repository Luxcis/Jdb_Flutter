# 排行榜影片详情导航设计

## 背景

排行榜中的影片卡片和 Top250 列表项当前未传入点击回调，用户点击影片后不会进入详情页。项目已经注册 `/movie/:id` 路由，首页和演员详情也使用 `context.push('/movie/${movie.id}')` 打开影片详情。

## 目标与范围

排行榜全部六个 Tab 的影片均可点击进入对应详情页：

- Top250
- 看热播
- 有码
- 无码
- 欧美
- FC2

本次只补充导航行为，不改变排行榜筛选、接口参数、分页、加载态、错误态、Tab 保活或卡片样式。

## 方案

在排行榜页面显式传入导航回调：

- Top250 的 `MovieListTile` 设置 `onTap`。
- 看热播和四个综合排行榜共用的 `MovieGridView` 设置 `onMovieTap`。
- 两种入口统一执行 `context.push('/movie/${movie.id}')`。

导航逻辑保留在排行榜 feature 页面中，不修改共享 `MovieGridView`、`MovieListTile` 或 `MovieCard` 的默认行为，避免分类、搜索、个人页等其他调用方被隐式改变。

## 数据与交互流程

1. 排行榜接口返回 `MovieSummary`。
2. 列表或网格组件渲染该影片。
3. 用户点击影片。
4. 排行榜页面读取 `movie.id` 并 push `/movie/{id}`。
5. 已注册的 GoRouter 路由创建 `MovieDetailPage(id: movie.id)`。
6. 用户返回后，排行榜原 Tab、筛选和已加载内容继续由现有保活逻辑保留。

## 错误处理

排行榜只负责传递已有影片 ID，不增加额外网络请求。详情页沿用现有加载、错误与重试逻辑。接口若没有影片项，则没有可点击入口。

## 测试

Widget 测试使用实际 GoRouter 路由状态验证：

- 点击 Top250 的列表影片后，当前路径为 `/movie/{id}`。
- 点击看热播的网格影片后，当前路径为 `/movie/{id}`。
- 四个综合排行榜复用与看热播相同的 `MovieGridView` 回调结构；至少点击其中一个代表 Tab 验证实际路径，其余由共享实现和现有类型映射测试覆盖。
- 导航测试使用占位详情页面，避免详情接口加载干扰排行榜点击行为。
- 现有排行榜 Widget 测试、接口集成测试、静态分析和全量测试继续通过。

## 非目标

- 不改变详情页 UI 或接口。
- 不让共享影片组件默认导航。
- 不改变返回手势或系统返回键行为。
- 不修改排行榜紧凑筛选的点击区域；按用户确认保留现有 `shrinkWrap` 配置。
