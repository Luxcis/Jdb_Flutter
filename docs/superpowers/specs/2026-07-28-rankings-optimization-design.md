# 排行榜功能优化设计

## 目标

优化排行榜页面的加载反馈、Tab 切换体验与筛选交互，并使排行榜相关请求严格符合 `docs/main/api/jdb_api_openapi.json` 的参数定义。

## 范围

- 为排行榜首次加载、筛选切换加载和分页加载提供明确反馈。
- 避免首次切换到尚未加载的 Tab 时出现空白页面。
- 保留已加载 Tab 的内容和滚动状态，返回该 Tab 时不重复首屏请求。
- 将“看热播”筛选改为两行分组圆角标签。
- 为 Top250 增加底部抽屉筛选。
- 删除有码、无码、欧美中的“演员月榜”。
- 修正 Top250、看热播和综合排行榜的请求参数。
- 使用 widget/service 测试、静态分析和 `adb_tool` 验证功能与样式。

不在本次范围内：

- 改动排行榜以外页面的视觉样式。
- 引入新的状态管理或 UI 依赖。
- 增加搜索功能。
- 修改 OpenAPI 文档。

## 页面与状态架构

`RankingsPage` 继续持有顶层 `TabController`，各排行榜 Tab 继续拥有独立的分页控制器。各 Tab 使用 keep-alive 保留已加载内容和滚动状态，避免切换回来时重新创建控制器。

分页控制器需要支持安全地替换查询函数并重新加载。重新筛选时清空旧结果、立即进入加载状态，并使用请求代次忽略已经过期的异步结果，防止用户快速连续选择筛选项时旧响应覆盖新响应。

加载状态分为三类：

1. 首次加载或筛选后列表为空：页面主体居中显示 `CircularProgressIndicator`。
2. 已有内容时加载下一页：列表或网格底部显示小型进度指示器，现有内容保持可见。
3. 请求失败且列表为空：显示现有 `ErrorRetryWidget`；已有内容时分页失败不替换当前内容。

## 顶部 Tab 与 Top250 筛选入口

顶部 Tab 保持以下顺序：

1. Top250
2. 看热播
3. 有码
4. 无码
5. 欧美
6. FC2

仅当 Top250 为当前 Tab 时，在 AppBar 右侧显示 `filter_alt_outlined` 筛选按钮，语义标签为“筛选 Top250”。点击后使用 Material 3 `showModalBottomSheet` 打开底部抽屉，启用拖动把手、安全区域和内容滚动。

## Top250 底部筛选抽屉

抽屉按参考图分为三部分：

### 类型或年份

- 第一行：全部、有码、无码、欧美、FC2。
- 后续年份：从设备当前年份倒序到 2008。
- 类型与年份属于同一个 OpenAPI 筛选维度，因此互斥选择。
- 默认选中“全部”。

映射规则：

| 界面选项 | `type` | `type_value` |
| --- | --- | --- |
| 全部 | `all` | 空字符串 |
| 有码 | `video_type` | `0` |
| 无码 | `video_type` | `1` |
| 欧美 | `video_type` | `2` |
| FC2 | `video_type` | `3` |
| 任一年份 | `year` | 四位年份字符串 |

### 起始排名

提供 `1`、`51`、`101`、`151`、`201`，默认选中 `1`，映射为 `start_rank`。

Top250 每次请求固定 `limit=50`，不同时传递 `page`，避免 OpenAPI 标注的 `page` 与 `start_rank` 叠加效应。每次请求展示所选起始排名对应的 50 条结果，影片排名从 `start_rank` 开始显示。

### 未标“看过”

使用 `SwitchListTile` 展示：

- 标题：未标「看过」
- 说明：仅查看还未被标记「看过」的影片
- 默认关闭
- 映射为字符串参数 `ignore_watched=true|false`

用户选中任一筛选项后立即刷新 Top250 结果，抽屉保持打开。新的选中态必须立即反映在抽屉中；请求期间页面列表区域显示加载反馈。

## 看热播筛选

采用已确认的方案 A：两行分组圆角标签。

- 第一行标签“范围”：高分、全部；默认高分。
- 第二行标签“周期”：日榜、周榜、月榜；默认日榜。
- 使用 Material 3 `ChoiceChip` 或等价主题化控件，选中项使用主题主色，未选中项使用主题表面色。
- 标签和选项使用 `Wrap`，在窄屏和大字体下允许换行，不截断文字。
- 切换选项后立即刷新结果。

接口映射：

| 界面选项 | 参数 |
| --- | --- |
| 高分 | `filter_by=high_score` |
| 全部 | `filter_by=all` |
| 日榜 | `period=daily` |
| 周榜 | `period=weekly` |
| 月榜 | `period=monthly` |

`/api/v1/rankings/playback` 不传递 OpenAPI 未定义的 `page` 或 `limit`。

## 有码、无码、欧美与 FC2

所有综合排行榜仅保留日榜、周榜、月榜，不再显示或请求“演员月榜”。

映射规则：

| Tab | `type` |
| --- | --- |
| 有码 | `0` |
| 无码 | `1` |
| 欧美 | `2` |
| FC2 | `3` |

周期映射为 `daily`、`weekly`、`monthly`。`/api/v1/rankings` 传递 OpenAPI 定义的 `page`，不传递未定义的 `limit`。

本页面不再使用 `/api/v1/rankings/actors`。

## 服务接口

`RankingService` 对外方法使用能够表达 OpenAPI 契约的参数：

- `getTop250(startRank, type, typeValue, ignoreWatched, limit)`
- `getPlayback(filterBy, period)`
- `getRanking(type, period, page)`

参数值在 UI 状态层使用常量或小型不可变值对象表达，避免继续使用当前含义颠倒的 `_filter`、`_period` 变量名。

响应继续通过 `ResponseInterceptor` 解包，服务从 `data.movies` 读取影片；兼容现有 `apiList` 的 `items` 后备键，不扩散响应兼容逻辑。

## 加载、错误与并发

- Tab 首次构建后立即开始首屏请求。
- 未返回数据前显示进度环，不显示空网格或空列表。
- 切换到已加载 Tab 时直接显示保留内容。
- 快速切换筛选项时，仅最后一次请求允许更新当前控制器状态。
- 筛选失败时提供重试，重试使用当前可见的筛选条件。
- 控制器和 `TabController` 在所属 State 销毁时释放。

## 测试与验收

### 服务契约测试

- Top250 请求包含正确的 `start_rank`、`type`、`type_value`、`ignore_watched`、`limit=50`，且不包含 `page`。
- 看热播请求使用 `high_score|all` 与 `daily|weekly|monthly`，且不包含 `page`、`limit`。
- 综合排行榜使用 `type=0|1|2|3`、正确周期和 `page`，且不包含 `limit`。

### Widget 测试

- 首次进入未完成请求的排行榜 Tab 时显示进度环。
- 切换到新 Tab 时显示进度环而非空白内容。
- 已加载 Tab 切走再返回时保留内容，且不重复首屏请求。
- 看热播显示“范围”“周期”和五个圆角筛选项，选择后发出正确请求。
- 有码、无码、欧美和 FC2 均不显示“演员月榜”。
- Top250 筛选按钮只在 Top250 Tab 显示。
- Top250 抽屉包含类型、当前年至 2008、起始排名和“未标「看过」”开关。
- Top250 选择类型、年份、起始排名或开关后立即请求，抽屉保持显示。
- 大字体和常见手机宽度下筛选控件无布局溢出。
