# 首页与列表页搜索入口设计

## 目标

为现有搜索页面补充四个清晰入口：

- 首页豆腐块上方展示整行搜索栏。
- 排行榜、类别、演员页面顶部导航栏右侧展示搜索图标。
- 点击任一入口进入现有 `/search` 搜索页面。

本次只增加搜索入口，不修改搜索接口、搜索结果、搜索历史或搜索页面内部交互。

## 交互设计

### 首页搜索栏

搜索栏位于首页滚动内容的最上方、`TofuScroll` 豆腐块之前，并随首页内容一起滚动。

搜索栏是展示型导航入口，不在首页直接接收文字输入。内部从左到右依次为：

1. 搜索图标。
2. 占位文案“输入演员或番号等关键字”。

整个搜索栏均可点击，点击后通过 `context.push(AppRoutes.search)` 进入搜索页面。搜索页面继续使用已有的自动聚焦输入框；用户返回时回到首页并保留底部导航壳层状态。

视觉样式遵循 Material 3，颜色从当前 `ColorScheme` 获取，同时支持亮色和暗色主题。搜索栏使用足够的点击高度、圆角和明确的点击反馈，并提供可被辅助功能识别的搜索语义。

### 顶部导航栏搜索按钮

排行榜、类别、演员页面的 `AppBar.actions` 最右侧增加搜索按钮：

- 图标使用 `Icons.search`。
- tooltip 使用“搜索”。
- 点击后通过 `context.push(AppRoutes.search)` 进入搜索页面。

排行榜原有 Top250 筛选按钮和类别原有筛选按钮保持不变，并排列在搜索按钮左侧。演员页原有各 Tab 及筛选行为保持不变。

## 代码组织

在 `lib/core/widgets/` 增加共享搜索入口组件，统一以下行为：

- 搜索图标、tooltip 和导航目标。
- 首页整行搜索栏样式与点击语义。
- AppBar 搜索图标按钮。

组件依赖 `AppRoutes.search` 和 `go_router` 完成导航。各业务页面只负责把对应形式的入口放入现有布局，不复制路由字符串或点击逻辑。

## 导航与状态

`/search` 是底部导航 `StatefulShellRoute` 之外的现有顶层路由。所有新增入口使用 `push`，让搜索页覆盖当前页面，并允许系统返回操作恢复来源页面及其当前 Tab。此次不使用 `go`，避免切换或重建底部导航分支。

## 测试策略

按测试驱动方式实现：

1. 首页 Widget 测试验证搜索栏位于豆腐块之前，并显示搜索图标及精确占位文案。
2. 路由 Widget 测试点击首页搜索栏后验证当前 URI 为 `/search`。
3. 排行榜、类别、演员页面测试验证 AppBar 搜索按钮存在。
4. 分别点击三个页面的搜索按钮，验证当前 URI 为 `/search`。
5. 验证排行榜和类别现有筛选按钮仍然存在，且搜索按钮为 actions 中最右侧入口。
6. 运行相关 Widget 测试、完整 `flutter test`、`flutter analyze` 和 `git diff --check`。

## 验收标准

- 首页豆腐块上方存在整行搜索栏。
- 搜索栏内容顺序为搜索图标、文案“输入演员或番号等关键字”。
- 点击首页搜索栏进入现有搜索页面。
- 排行榜、类别、演员页面 AppBar 右侧均有搜索图标。
- 点击任一顶部搜索图标进入现有搜索页面。
- 原有筛选入口、Tab 状态、首页豆腐块尺寸和搜索页行为不受影响。
- 不新增第三方依赖。
