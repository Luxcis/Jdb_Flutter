# Top250 无限滚动加载设计

## 背景

Top250 当前只请求筛选起始排名对应的一批数据。`/api/v1/movies/top` 虽然接受 `page`，但本地 OpenAPI 明确说明 `page` 与 `start_rank` 存在叠加效应，建议仅使用 `start_rank` 控制分页；接口默认每批返回 50 条。

用户希望 Top250 列表支持瀑布流式自动加载。本设计将其解释为保持现有单列排行榜样式，在用户滚动接近底部时自动追加下一批数据，不改为多列瀑布流布局。

## 目标与范围

- Top250 距离列表底部约 200 逻辑像素时自动加载下一批。
- 每批最多请求 50 条，仅通过递增的 `start_rank` 控制请求范围。
- 从当前筛选选择的起始排名继续加载，最多加载至第 250 名。
- 追加加载期间保留已展示内容，并在列表底部显示加载状态。
- 追加加载失败时保留已有内容，并提供底部重试入口。
- 下拉刷新、切换 Top250 筛选或登录状态变化后，从当前起始排名重新加载。

本次不改变 Top250 的单列样式、筛选抽屉、影片详情导航、其他排行榜 Tab 或共享分页控制器的通用行为。

## 数据请求设计

Top250 使用固定批量大小 `50`。页面分页序号从 1 开始，请求起始排名按以下公式计算：

```text
requestStartRank = selectedStartRank + (page - 1) * 50
```

示例：

- 选择第 1 名：依次请求 1、51、101、151、201。
- 选择第 51 名：依次请求 51、101、151、201。
- 选择第 201 名：只请求 201。

请求继续保留当前 `type`、`type_value` 和 `ignore_watched` 筛选参数，不发送 `page`。

由于该接口的分页边界由排名而非标准页码决定，页面在取得服务响应后为共享 `PaginationController` 构造本地逻辑分页信息：

- `currentPage` 使用当前逻辑页码。
- `totalPages` 根据所选起始排名到 250 的剩余范围计算。
- 当接口返回少于 50 条时，将当前页视为最后一页，避免无意义的后续请求。
- 当最后一批恰好为空时结束加载，并保留此前已加载内容。

服务层继续负责构造符合 OpenAPI 的请求和解析影片数据；Top250 页面负责把排名范围映射为逻辑分页，因为所选起始排名属于页面筛选状态。

## 交互与状态

Top250 列表通过滚动通知监听剩余可滚动距离。当滚动结束且 `extentAfter < 200` 时调用现有 `PaginationController.fetchMore()`。控制器已有加载中和无更多数据保护，可避免同一时刻重复请求。

列表项排名继续按以下方式显示：

```text
displayRank = selectedStartRank + accumulatedItemIndex
```

加载和错误状态分为：

- 首次加载：列表为空时显示居中进度环。
- 首次加载失败：显示现有整页错误与重试组件。
- 追加加载：已有列表保持可见，底部显示小型进度环。
- 追加加载失败：已有列表保持可见，底部显示“加载失败，点击重试”入口。
- 无更多数据：不显示额外占位，不再触发请求。

下拉刷新和筛选变化沿用 `reloadWith` 的代际保护，清空旧列表并重新从逻辑第 1 页加载，避免旧请求覆盖新筛选结果。

## 组件边界

- `RankingService`：继续按 `start_rank` 和现有筛选字段请求 `/api/v1/movies/top`，不发送 `page`。
- `_Top250TabState`：将逻辑页映射为实际起始排名，计算 Top250 的本地页数。
- Top250 列表：监听接近底部事件，渲染追加加载或追加失败的底部状态。
- `PaginationController`：复用现有串行加载、刷新、错误和代际隔离能力，不加入 Top250 专用知识。

## 测试策略

1. 服务契约测试继续断言 Top250 请求包含 `start_rank`、筛选字段和 `limit=50`，且不包含 `page`。
2. Widget 测试滚动 Top250 到列表底部，断言第二次请求的 `start_rank` 从 1 递增到 51，原有列表仍然存在，新数据被追加。
3. 起始排名测试选择 51 后触发自动加载，断言请求依次为 51、101，并验证追加影片显示排名连续。
4. 边界测试从 201 开始只请求一批，滚动到底后不再请求。
5. 短页测试验证返回少于 50 条时停止自动加载。
6. 追加加载中的 Widget 测试验证已有内容保持可见且底部显示进度环。
7. 追加加载失败测试验证已有内容保持可见、底部出现重试入口，点击后重新请求同一批。
8. 运行排行榜聚焦测试、API 集成测试、静态分析及全量 Flutter 测试。

## 验收标准

- Top250 首批加载后，继续向下滚动可无缝追加后续排名。
- 自动加载只使用 `start_rank`，请求序列与所选起始排名一致。
- 不超过第 250 名，不重复发起已完成的末页请求。
- 追加加载和失败不会先清空当前列表或展示空白界面。
- 下拉刷新及筛选切换后不会混入旧筛选的响应。
- 影片点击仍进入对应详情页，其他排行榜 Tab 行为不受影响。

## 非目标

- 不把 Top250 改为多列 Masonry/Grid 布局。
- 不预先一次性请求全部剩余影片。
- 不修改 OpenAPI 文档。
- 不改变 Top250 筛选抽屉尺寸或紧凑胶囊控件。
