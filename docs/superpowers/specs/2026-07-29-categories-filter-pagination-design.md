# 分类页独立筛选与自动分页设计

## 目标

根据参考截图重构分类页，在“有码、无码、欧美、FC2、动漫”五个 Tab
中提供相互独立的筛选、排序、标签字典、影片分页数据和滚动状态。筛选项点击后立即生效，
影片列表采用三列等高网格，并在接近底部时自动加载下一页。

## 约束

- 接口路径、分页和排序参数以 `docs/main/api/jdb_api_openapi.json` 为准；
  `filter_by` 的段位、默认值和月份格式以本设计记录的最新产品确认覆盖文件中的旧描述。
- Tab 类型严格使用 `0` 到 `4`：
  - `0`：有码
  - `1`：无码
  - `2`：欧美
  - `3`：FC2
  - `4`：动漫
- 标签字典使用 `GET /api/v2/tags?type={type}`。
- 分类影片使用 `GET /api/v1/movies/tags`。
- 筛选面板的分组、分组名称和筛选项全部来自 `/api/v2/tags`，客户端不硬编码筛选内容。
- `filter_by` 固定为 `{type}:t:{main}:{extra}:{year}:{duration}:{month}`，
  其格式本身与标签 ID 无关，段位含义不随标签分组改变。
- 五个 Tab 首次请求依次使用 `0:t:::::`、`1:t:::::`、`2:t:::::`、
  `3:t:::::`、`4:t:::::`。
- 每页固定请求 `limit=48`。
- 影片区域使用三列等高网格，不引入 Masonry 依赖。
- 影片卡片必须复用现有 `MovieCard`，不新增分类专用卡片，也不在本功能中改变共享卡片契约。
- 图片继续由现有卡片优先使用 `thumb_url`，缺失时回退 `cover_url`，并保持比例显示。
- 继续使用 Material 3、系统字体、亮暗主题；所有新增文案直接使用中文硬编码。
- 不增加参考截图中语义不明确的“眼睛”按钮功能。

## 方案选择

采用“每个 Tab 一个独立状态控制器，分类页只负责协调 Tab 和底部筛选面板”的方案。

不采用以下方案：

- 单一页面状态加五份 Map：会将接口、筛选、分页和 UI 状态耦合在一个页面中。
- 切换 Tab 时重建：会丢失筛选和滚动状态，并重复加载标签字典。

## 架构

### 分类筛选模型

定义不可变筛选值对象，包含：

- `main`：`main` 分组当前选中值，空值表示全部。
- `extraValues`：除 `main/year/duration/month` 外其他动态分组选中值的集合。
- `year`：`year` 分组当前选中值，空值表示全部。
- `duration`：`duration` 分组当前选中值，空值表示全部。
- `month`：`month` 分组当前选中值，空值表示全部。
- `sortBy`：排序字段。
- `orderBy`：发布日期排序方向。

模型负责稳定地生成固定七段 `filter_by`：

```text
{type}:t:{main}:{extra}:{year}:{duration}:{month}
```

字段映射：

- `type`：当前 Tab 类型 `0` 到 `4`。
- 第二段：固定字面值 `t`。
- `main`：`p` 可播放、`m` 可下载、`c` 有字幕、`s` 单体系列、
  `i` 预告图、`v` 预告片，或空值。
- `extra`：附加筛选值，多个值用英文逗号连接，或空值。
- `year`：年份值，例如 `2024`，或空值。
- `duration`：时长值，例如 `120`，或空值。
- `month`：月份值，例如 `01`，或空值。

空段必须保留冒号。`extra` 使用接口分组顺序和分组内选项顺序稳定输出，
保证请求和测试可预测。首次进入页面时所有可选段均为空。

排序字段：

- `release`：发布日期
- `update`：更新时间
- `score`：评分
- `hit`：热度
- `want_watch_count`：想看人数
- `watched_count`：看过人数

仅当 `sort_by=release` 时发送 `order_by=asc|desc`。

### 标签模型与服务

为 `/api/v2/tags` 响应定义标签分组和标签项模型：

- 标签分组包含 `category`、`category_id` 和 `tags`。
- 标签项包含 `id`、`name` 和 `videos_count`。

筛选面板直接遍历接口返回的标签分组，并按接口顺序展示 `category` 和 `tags`。
客户端不预设分组名称或补充本地分组。每个选项使用接口返回的 `id` 作为筛选值，
但写入哪个 `filter_by` 段由稳定的 `category_id` 决定，而不是把所有 ID
统一写入同一段：

- `category_id=main` 写入 `main`。
- `category_id=year` 写入 `year`。
- `category_id=duration` 写入 `duration`。
- `category_id=month` 写入 `month`。
- 其他 `category_id` 的选中值合并写入 `extra`。

接口对不同 Tab 返回不同分组时，各 Tab 按自己的响应独立构建面板。

`CategoryService` 提供：

- 按 Tab 类型加载标签字典。
- 按筛选值、页码加载影片。

影片请求不再发送旧的独立 `type` 参数，也不再发送
`filter_by=categories`，而是发送完整 `filter_by`、排序参数、`page` 和
`limit=48`。

分页响应优先读取 OpenAPI 的 `total_count`，同时兼容已有响应中的 `total`。

### Tab 状态控制器

五个 Tab 各自持有一个长生命周期状态控制器，状态包括：

- 当前筛选和排序。
- 标签字典、标签加载状态和标签加载错误。
- 影片列表、当前页、是否还有下一页。
- 首次加载、筛选刷新、加载更多和分页错误状态。
- 本 Tab 的滚动控制器或可恢复滚动位置。

控制器行为：

1. 首次进入 Tab 时并行加载标签字典和第一页影片。
2. 标签字典在页面生命周期内只成功加载一次；失败时支持局部重试。
3. 任一筛选或排序变化后，立即使当前结果代次失效，从第一页重新请求。
4. 旧请求晚于新请求返回时，通过代次标识丢弃旧结果。
5. 加载更多时只允许一个请求在途，成功后按页序追加。
6. 没有下一页时停止触发请求。
7. 下拉刷新保留筛选值，仅重载第一页。
8. 切换 Tab 不修改其他 Tab 的筛选、影片和滚动状态。

## 页面设计

### 顶部区域

- AppBar 标题保持“类别”。
- 五个 Tab 使用可读的紧凑布局，选中项使用主题主色和底部指示线。
- 提供筛选入口；不添加没有明确产品语义的按钮。

### 影片区域

- 使用现有 `MovieGridView`/`MovieCard` 组合，必要时只扩展网格容器的分页触发和状态展示能力。
- 保持三列等高网格和懒构建。
- 滚动距离底部约 `400px` 时预取下一页，而不是等待滚动完全停止。
- 首次加载显示居中进度。
- 筛选刷新时保留已有列表并展示轻量刷新反馈，避免页面闪白。
- 加载更多时在网格底部显示进度。
- 加载更多失败时保留已有影片并提供重试。
- 下拉刷新重载第一页。

### 紧凑筛选面板

筛选入口打开可滚动的模态底部面板：

- `isScrollControlled`，顶部圆角和拖动柄，最大高度约为屏幕的 90%。
- 标题左侧显示“筛选”，右侧显示当前排序；发布日期排序可切换升降序。
- 分组名使用固定宽度窄列，选项区域使用紧凑 `FilterChip` 和 `Wrap`。
- 面板仅展示 `/api/v2/tags` 返回的动态分组和筛选项。
- `main`、`year`、`duration`、`month` 分组单选；再次点击已选项时清空该段。
- 其他动态分组允许多选，其选中值跨分组合并进入 `extra` 段。
- 客户端不硬编码“基础、年份、月份、时长”等分组或选项。
- 点击任何选项后立即更新当前 Tab 并刷新第一页，面板保持打开。
- 面板关闭后选择保持；再次打开显示当前 Tab 的已选值。
- 切换 Tab 后面板展示目标 Tab 自己的筛选值和标签状态。
- 标签过多时仅面板内容滚动，不影响后方影片列表位置。
- 标签加载失败时在面板内显示错误和重试入口。

## 错误与并发处理

- 首屏影片失败：显示页面级错误与重试。
- 已有影片时加载更多失败：保留列表，在底部显示重试。
- 标签失败：不阻塞影片列表，筛选面板内独立重试。
- 任何筛选变化都会增加请求代次；只允许当前代次更新列表。
- 快速滚动触发多次阈值通知时，由控制器的在途状态去重。
- 页面销毁后忽略未完成请求结果，不再通知监听器。

## 测试设计

### 模型和服务测试

- `filter_by` 固定使用 `{type}:t:{main}:{extra}:{year}:{duration}:{month}`。
- 五个 Tab 的首次请求分别为 `0:t:::::` 到 `4:t:::::`，不默认选择 `main`。
- `main/year/duration/month` 根据 `category_id` 写入各自段位。
- 其他动态分组选中值跨分组稳定拼接到 `extra`，多个值使用英文逗号。
- Tab 类型使用 `0` 到 `4`。
- 影片请求发送正确的 `sort_by`、条件化 `order_by`、`page` 和 `limit=48`。
- 标签请求发送正确的 `type` 并解析标签分组。
- 面板分组、名称和选项均来自标签响应，不混入本地硬编码筛选内容。
- 分页总数兼容 `total_count` 和 `total`。

### 状态测试

- 五个 Tab 的筛选值互不影响。
- 筛选变化从第一页重新请求。
- 旧代次响应不会覆盖新结果。
- 下一页按顺序追加且不能并发重复加载。
- 无下一页时停止请求。
- 下拉刷新保留筛选条件。
- 标签字典成功后不重复请求，失败后可重试。

### Widget 测试

- 页面展示五个 Tab 和三列影片网格。
- 影片项使用现有 `MovieCard`。
- 筛选面板以紧凑分组和选项展示。
- 点击筛选项无需确认按钮即可触发当前 Tab 重载。
- 切换 Tab 后筛选选择和影片状态独立，切回后恢复。
- 接近底部时自动请求下一页。
- 亮暗主题和较大文字比例下不发生布局溢出。

## 验收标准

- 五个 Tab 与 OpenAPI 的 `0` 到 `4` 类型映射一致。
- 每个 Tab 的筛选、排序、标签、影片、分页和滚动状态完全独立。
- 筛选点击后立即生效，不需要确认按钮。
- 首次进入各 Tab 时，`filter_by` 仅包含对应类型和固定 `t`，其余五段为空。
- 请求参数符合 OpenAPI，分页固定为每页 48 条。
- 三列等高网格接近底部时自动加载下一页。
- 筛选面板采用参考截图的紧凑底部面板布局。
- 筛选面板内容完全由当前 Tab 的 `/api/v2/tags` 响应动态构建。
- 影片卡片复用现有组件。
- 快速筛选不会出现旧响应覆盖新结果。
- 定向测试、完整测试和静态分析通过。
