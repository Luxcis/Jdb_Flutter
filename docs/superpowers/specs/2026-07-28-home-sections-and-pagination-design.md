# 首页分区样式与分页换组设计

## 目标

根据参考图统一首页入口卡片、分区标题和“换一组”控件样式，并将“最新上架”“近期磁链更新”改为使用 `/api/v1/movies/latest` 的独立分页请求。首个分区标题固定为“最新上架”。

## 范围

- 调整首页顶部横向功能入口的卡片外观。
- 全局调整共享 `SectionHeader` 的标题与尾部入口样式。
- 调整首页两个影片分区底部的“换一组”控件。
- 修正两个首页分区的初始请求和后续分页请求。
- 为请求参数、分页状态与关键组件交互补充自动化测试。

不新增依赖，不修改路由目标，不调整影片卡片内容，不修改现有 OpenAPI 文档改动。

## 视觉设计

### 顶部功能入口

`TofuScroll` 保持横向滚动和现有入口顺序。每个入口使用固定宽度的圆角卡片，包含浅色背景、细边框和轻阴影；图标位于上方并使用区分入口的主题友好颜色，中文标签位于下方。卡片通过 `InkWell` 提供 Material 点击反馈，并保留现有路由。

### 全局分区标题

共享 `SectionHeader` 全局改为参考图层级：

- 左侧标题使用更大的加粗主题文本。
- 右侧尾部文案使用次要前景色。
- 存在尾部文案时，在文案右侧显示向右箭头。
- `onTrailing` 非空时整组尾部区域可点击；为空时仅展示，不虚构导航行为。
- 保留 `bold` 参数兼容现有调用，但新标题层级本身已具备明确强调。

该变更会同步影响首页和演员页等所有现有 `SectionHeader` 调用，这是已确认的全局行为。

### 换一组

首页每个影片网格下方使用整行、居中的文本按钮，文案为“换一组”，右侧使用刷新图标。按钮加载时禁用并显示小型进度指示，避免同一分区重复发起请求。

## 数据与状态设计

`HomeService` 为两个分区分别提供明确的方法，但统一请求 `Endpoints.moviesLatest`：

### 最新上架

```text
type=all
filter_by=can_play
sort_by=update
order_by=desc
limit=9
page=<当前页>
```

### 近期磁链更新

```text
type=all
filter_by=magnets
sort_by=update
order_by=desc
limit=9
page=<当前页>
```

`HomeProvider` 为两个分区分别维护页码和加载状态。初始加载均请求第 1 页；点击对应“换一组”后先计算下一页，再用该页码请求并以新响应替换当前 9 张卡片。两个页码互不影响。

请求成功后提交新页码和新列表。请求失败时保留当前页码与影片列表，使用户可以重试同一下一页；页面通过 `SnackBar` 提示失败。返回空列表属于成功响应，页面显示现有空状态，下一次点击继续请求后续页。

## 组件边界

- `HomeService`：构造精确查询参数并解析影片列表。
- `HomeProvider`：维护首页初始状态、两个独立页码及换组加载状态。
- `HomePage`：组合分区、触发异步换组、展示加载与错误反馈。
- `TofuScroll`：实现首页入口卡片视觉和交互。
- `SectionHeader`：提供全局统一分区标题视觉。

不将网络逻辑放入 widget，不在共享 `SectionHeader` 中加入首页路由知识。

## 测试策略

1. 服务契约测试断言两个方法都请求 `/api/v1/movies/latest`，并逐项验证 `type`、`filter_by`、`sort_by`、`order_by`、`limit`、`page`。
2. Provider 测试验证两个分区初始页为 1，换组请求页依次递增，且两个分区页码互不影响。
3. Provider 失败测试验证请求失败后保留当前影片和已提交页码，并允许重试相同下一页。
4. Widget 测试验证入口使用卡片与点击反馈、全局标题尾部包含右箭头、“换一组”使用刷新图标。
5. Widget 交互测试验证加载期间对应按钮不可重复触发，并在完成后更新内容。
6. 运行首页聚焦测试、相关 API 测试与 `flutter analyze`。

## 验收标准

- 首页入口、标题和换组区域在明暗主题下均可读，不出现小屏横向溢出。
- 首个分区标题显示“最新上架”。
- 两个初始请求均使用页码 1 和限制 9，其他参数与需求中的 curl 一致。
- 每次点击只让对应分区请求下一页并替换该分区卡片。
- 请求中不会硬编码用户提供的临时 `jdsignature`；签名仍由现有网络层生成。
- 现有未提交 OpenAPI 文档改动保持原样且不进入本功能提交。
