# 搜索入口页与热词设计

## 目标

将现有搜索页拆分为搜索入口页和搜索结果页：搜索入口页只展示搜索输入、历史搜索和 startup 近期热词；用户执行搜索后进入独立结果页。

本次接入 startup 返回的 `recent_keywords`，不解析、不保存、不展示 `recent_magnet_keywords`。

## 数据来源

### 历史搜索

历史搜索继续使用 `SharedPreferences` 中的 `StorageKeys.searchHistory`：

- 用户提交输入或点击任一历史、热词标签时记录关键词。
- 关键词先去除首尾空白，空字符串不执行搜索。
- 相同关键词去重，最近执行的关键词移动到首位。
- 最多保留 20 条。
- 点击“清空”删除本地缓存并立即隐藏整个历史搜索模块。

### 近期热搜

`StartupData` 按 OpenAPI 契约解析 `recent_keywords` 为 `List<String>`。`StartupProvider` 在 startup 成功后保存本次返回的列表并向页面提供只读访问。

搜索页从 `StartupProvider` 读取近期热词。热词不额外写入 `SharedPreferences`；只有用户点击并实际执行搜索后，该关键词才进入历史记录。

缺失或空的 `recent_keywords` 按空列表处理，不影响 startup 既有域名发现、失败重试或进入首页的规则。

## 页面与导航

### 搜索入口页 `/search`

搜索入口页包含顶部搜索输入框和最多两个内容模块，不渲染任何搜索结果。

模块顺序固定为：

1. 历史搜索。
2. 近期热搜。

历史搜索模块仅在历史列表非空时存在。标题“历史搜索”使用较大的加粗文字；“清空”按钮与标题同行并对齐屏幕右侧。

近期热搜模块仅在 `recent_keywords` 非空时存在。标题“近期热搜”使用与历史模块相同的较大加粗样式。

如果两类数据均为空，输入框下方不显示模块标题或空状态文案。

### 搜索结果页 `/search/results?q=<关键词>`

用户在入口页提交输入或点击标签时：

1. 更新并持久化历史搜索。
2. 使用 URI query parameter 编码关键词。
3. `push` 到 `/search/results?q=<关键词>`。

搜索结果页承接现有的影片、演员、系列、片商、导演、清单、番号七个 Tab 及其网络逻辑。顶部输入框预填当前关键词；重新提交有效关键词时更新历史，并使用 `replace` 替换当前结果路由，避免连续搜索堆叠多个结果页。系统返回操作回到搜索入口页。

路由缺少 `q` 或关键词去除首尾空白后为空时，重定向回 `/search`，不发起搜索请求。

## 标签样式与交互

历史和热词都使用相同的紧凑可点击标签组件：

- 使用 `ActionChip`。
- 采用紧凑视觉密度和较小内边距。
- 通过 `Wrap` 自动换行，避免窄屏溢出。
- 标签文字来自原始关键词。
- 点击标签执行与输入框提交相同的搜索流程。

标题样式统一从当前 Material 3 `TextTheme` 获取，使用 `titleLarge` 并加粗，不硬编码颜色，以支持亮色和暗色主题。

## 代码边界

- `StartupData`：负责解析 `recent_keywords`。
- `StartupProvider`：在成功加载后保存并暴露近期热词，不负责本地历史。
- `SearchPage`：负责入口页输入、历史加载、清空和发起导航。
- `SearchResultsPage`：负责结果页输入及现有七类结果内容。
- 搜索历史的读取、去重、上限和持久化保留在搜索 feature 内，不扩散到 startup 层。

## 异常与生命周期

- 历史缓存缺失、JSON 非列表或含非字符串项时按空列表处理，避免搜索入口页崩溃。
- 异步读取或清空历史后，仅在 Widget 仍 mounted 时更新页面。
- startup 重试成功时以最新 `recent_keywords` 替换旧列表。
- startup 失败时维持现有启动页失败门禁，搜索页不会提前显示。

## 测试策略

按测试驱动方式覆盖：

1. `StartupData.fromJson` 正确解析 `recent_keywords`，缺失时返回空列表。
2. `StartupProvider` 成功后暴露热词，重试成功使用最新列表。
3. 搜索入口页按“历史搜索、近期热搜”顺序显示非空模块，标题为大号加粗样式，历史清空按钮同行靠右。
4. 历史或热词为空时对应标题不存在；两者都为空时不显示任何模块。
5. 历史和热词使用紧凑标签且窄屏可换行。
6. 输入提交或标签点击会更新历史并导航到编码后的 `/search/results?q=<关键词>`。
7. 搜索入口页不包含结果 Tab；结果页包含现有七个 Tab。
8. 结果页重新搜索时替换当前 URI，返回后仍是搜索入口页。
9. 缺少或空白 `q` 时返回 `/search` 且不发起请求。

## 验收标准

- 搜索入口页只显示输入框、非空历史模块和非空近期热搜模块。
- 历史标题同行右侧显示清空按钮。
- 所有模块标题使用统一的大号加粗样式，内容使用紧凑标签。
- 空模块不保留标题或占位文案。
- 执行搜索后打开独立结果页，入口页不展示结果。
- 结果页保留现有七类搜索能力，并支持替换当前关键词。
- 近期热词严格来自 startup 的 `recent_keywords`。
- `recent_magnet_keywords` 不进入模型、Provider 或 UI。
