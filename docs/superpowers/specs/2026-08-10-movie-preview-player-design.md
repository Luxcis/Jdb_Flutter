# 影片详情预告片播放器设计

## 目标

当影片详情接口返回非空 `preview_video_url` 时，在“预告片 / 剧照”横向列表首位展示带播放标识的影片封面。用户点击后进入只允许横屏的预告片播放页，使用官方 `video_player` 播放该 M3U8 地址。

本次只实现详情接口提供的预告片播放，不扩展正片播放、清晰度选择、投屏、下载、字幕、后台播放或画中画。

## 数据契约

以 `docs/main/api/jdb_api_openapi.json` 的影片详情结构为准：

- `preview_video_url` 为可选字符串。
- `normalizeMovieDetailJson` 负责读取并清理该字段。
- 缺失、`null`、空字符串或仅包含空白字符时，统一归一化为 `null`。
- `MovieDetail` 增加 `String? previewVideoUrl`，并保持 JSON 序列化生成代码同步。

详情页直接使用已加载的 `previewVideoUrl`，进入播放页时不重复请求详情接口。

## 详情页入口

“预告片 / 剧照”区域的显示规则调整为：

- 存在预告片或普通剧照任一内容时显示该区域。
- 存在预告片时，第一项固定为影片封面预告入口。
- 预告入口使用现有 `MovieCoverImage`，按 `16:9` 容器裁切，中央叠加有半透明背景的高对比播放图标。
- 预告入口具有独立的 key 和无障碍语义“播放《影片标题》预告片”。
- 普通剧照紧随其后，原始顺序不变。
- 预告封面不加入 `ImageGalleryViewer` 的图片集合，因此剧照图库的数量、初始索引和翻页行为不变。
- 没有预告片时，现有剧照展示与点击行为保持不变。

即使影片没有普通剧照，只要存在预告片，也应显示只有一个预告入口的该区域。

## 路由与参数

新增预告片播放路由 `/movie/:id/preview`，由影片详情页通过 `go_router` 打开。

路由使用类型明确的参数对象传递：

- 影片 ID；
- 影片标题；
- 已清理的预告片 URL。

URL 不放入查询字符串，避免带签名参数的 M3U8 地址被二次编码、暴露在路由文本中或被截断。该页面只从影片详情页入口打开；若路由参数缺失或 URL 无效，播放页显示错误状态，不尝试播放。

## 播放页结构

播放页属于 `movie_detail` feature，采用黑色沉浸式背景。只添加官方 `video_player` 依赖，不引入 Chewie 或其他控制层插件。

页面职责分为两层：

1. 播放生命周期层：创建、初始化、播放、暂停、倍速、重试和释放 `VideoPlayerController`。
2. 手势与控制层：展示播放器状态并把手势转换为明确的播放命令。控制层不负责网络初始化，便于独立进行 widget 测试。

播放器初始化成功后立即自动播放，并使用视频自身宽高比在可用横屏区域内居中显示；剩余区域保持黑色。

## 横屏与系统状态

进入播放页后：

- 在开始初始化播放器前，通过 `SystemChrome.setPreferredOrientations` 限制为 `landscapeLeft` 和 `landscapeRight`。
- 播放期间不允许切换到竖屏。
- 页面使用安全区域处理刘海和系统手势区域。

退出播放页或页面销毁时：

- 先暂停并释放播放器；
- 将首选方向恢复为空列表，交还给操作系统和应用默认方向策略；
- 无论初始化成功、初始化失败或用户提前退出，都必须执行方向恢复。

## 手势与控制层

手势契约如下：

- 单击画面：切换控制层显示或隐藏，不改变播放状态。
- 双击画面：切换播放或暂停，同时短暂显示控制层。
- 长按开始：将播放速度切换为 `2.0×`，显示居中的“2.0×”提示。
- 长按结束或取消：立即恢复 `1.0×`，隐藏倍速提示。
- 页面退出时若仍处于长按状态，也必须恢复默认倍速后释放播放器。

控制层包含：

- 左上角返回按钮和影片标题；
- 居中的播放或暂停按钮；
- 底部当前时间、总时长和可拖动进度条；
- 初始化和缓冲指示；
- 播放错误信息与重试按钮。

控制层自动隐藏规则：

- 自动播放开始或任意播放中操作完成后，重新开始 3 秒倒计时。
- 连续 3 秒无操作且视频正在播放时隐藏。
- 暂停、初始化、缓冲错误和播放错误状态下保持显示。
- 用户拖动进度条或长按倍速期间不自动隐藏；操作结束后重新计时。
- 所有定时器在页面销毁时取消，销毁后不得更新界面。

## 错误与边界处理

- URL 无法解析、播放器初始化失败或媒体播放失败时，显示“预告片播放失败”和重试操作。
- 重试会释放旧控制器并为同一 URL 创建新控制器。
- 初始化过程中退出页面不得触发销毁后的 `setState`。
- 视频时长未知时不显示错误时长，进度控件保持不可拖动状态。
- 视频播放到结尾后保持控制层可见；再次点击播放时从头开始。
- Android 已具备网络权限，不新增明文流量权限；若接口以后返回 HTTP 地址，应把平台安全策略作为独立需求处理，不在本次放宽全局网络安全配置。

## 测试策略

按 TDD 顺序覆盖以下行为：

### 数据测试

- OpenAPI 形状的详情数据正确解析 `preview_video_url`。
- 缺失、空字符串和空白字符串归一化为 `null`。
- `MovieDetail` JSON 映射包含新字段且生成代码一致。

### 详情页 widget 测试

- 有预告片时，封面预告入口位于普通剧照之前，并显示播放图标。
- 只有预告片、没有普通剧照时仍显示区域。
- 无预告片时不显示预告入口，普通剧照行为不变。
- 点击预告入口进入播放路由。
- 点击第二项普通剧照仍打开图库第 1 张，图库总数不包含预告封面。
- 预告入口具有正确的按钮语义标签。

### 播放控制 widget 测试

- 单击只切换控制层。
- 双击切换播放与暂停。
- 长按开始请求 `2.0×`，结束或取消请求恢复 `1.0×`。
- 播放中无操作 3 秒隐藏控制层。
- 暂停、拖动和错误状态不会被定时器隐藏。
- 销毁后定时器不再触发状态更新。

### 播放页与路由测试

- 路由参数完整时创建播放页，缺失时显示错误状态。
- 初始化成功后自动播放。
- 初始化失败时显示错误与重试。
- 进入页面请求左右横屏，退出时恢复默认方向。
- 控制器在重试和退出时正确释放。

## 验证

实现完成后依次执行：

1. `dart format` 格式化相关 Dart 文件；
2. 数据归一化聚焦测试；
3. 影片详情 widget 聚焦测试；
4. 播放器控制与路由聚焦测试；
5. `flutter analyze`；
6. 完整 `flutter test`。

任何由 Flutter SDK 缓存写权限导致的失败应单独标记为环境问题，不得当作代码测试通过。
