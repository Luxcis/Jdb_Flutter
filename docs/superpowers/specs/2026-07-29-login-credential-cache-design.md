# 登录凭据安全缓存设计

## 背景

应用在认证 token 过期后会统一清除 token/user，并携带当前路由跳转登录页。
当前登录页不会记住上一次成功登录的用户名和密码，用户需要重复输入。

本次功能要求：

- 登录成功后缓存用户名和密码。
- token 过期后再次进入登录页时自动填充两项。
- 用户主动退出时删除密码缓存，但保留用户名缓存。
- 自动填充表单，不自动提交登录请求。

## 安全边界

用户名和密码均使用 `flutter_secure_storage` 保存，不写入
`SharedPreferences`。Android 端由插件使用系统安全存储能力保护数据。

禁止：

- 将密码写入普通偏好设置、日志或异常文案。
- 在测试和文档中使用真实用户名或密码。
- 因自动填充而自动触发登录请求。

## 架构

在 `lib/core/` 下新增独立登录凭据存储能力，不让 `AuthProvider` 持有或暴露
密码。

核心接口：

- `SavedLoginCredentials`
  - `username`
  - 可空的 `password`
- `LoginCredentialStore`
  - `read()`：读取已保存凭据。
  - `save(username, password)`：保存最近一次成功登录的凭据。
  - `clearPassword()`：仅删除密码，保留用户名。

生产实现使用 `FlutterSecureStorage`。登录页和主动退出入口通过可替换的接口
使用该能力，以便 Widget 测试使用内存 fake，不调用真实平台通道。

## 登录页数据流

### 初始化

1. 登录页在 `initState()` 后异步读取安全凭据。
2. 已保存用户名非空时填入用户名输入框。
3. 已保存密码非空时填入密码输入框。
4. 读取完成前若用户已经在某个输入框中输入内容，不覆盖该输入框的现值。
5. 读取失败时保持现有表单内容，不阻止用户手动登录。
6. 自动填充完成后不自动提交。

### 登录成功

1. 用户名仍按现有契约执行 `trim()`。
2. 密码保持输入框原值。
3. 服务端返回成功响应后，将用户名和密码保存到安全存储。
4. 继续完成现有 token/user 持久化和成功路由跳转。
5. 凭据保存失败时不回滚服务端登录结果，也不阻止 token/user 保存和成功跳转。

### 登录失败

- 不修改已保存凭据。
- 输入错误、网络错误或设备参数错误均不能覆盖最后一次成功登录凭据。

## 退出语义

### token 过期

沿用当前全局认证失效链路：

1. `ResponseInterceptor` 识别认证错误。
2. `main.dart` 调用 `AuthProvider.logout()` 清除 token/user。
3. `AppRouter.goLoginForAuthError()` 携带 `from` 跳转登录页。
4. 不调用 `LoginCredentialStore.clearPassword()`。
5. 登录页读取并填充已保存的用户名和密码。

### 用户主动退出

个人页“退出登录”执行：

1. 调用 `LoginCredentialStore.clearPassword()`。
2. 无论密码删除是否成功，都继续调用 `AuthProvider.logout()` 清除 token/user。
3. 返回首页。
4. 下次进入登录页时填充用户名，密码框保持为空。

安全存储删除失败不应让用户停留在已登录状态；该错误与会话退出分开处理。

## 错误处理

- 读取失败：忽略缓存，保留当前表单，不显示敏感错误详情。
- 保存失败：登录仍视为成功，继续认证持久化和跳转。
- 删除失败：仍完成主动退出，不输出密码或安全存储中的内容。
- 所有异常处理均不得记录用户名和密码值。

## 测试策略

### 凭据存储单元测试

- 保存后能够读取用户名和密码。
- `clearPassword()` 删除密码但保留用户名。
- 无缓存时返回空结果。

### 登录页 Widget 测试

- 同时存在用户名和密码时自动填充两项。
- 只有用户名时只填用户名。
- 异步读取完成前的用户输入不会被覆盖。
- 自动填充不会自动发送登录请求。
- 登录成功后保存 trim 后的用户名和原始密码。
- 登录失败不修改缓存。
- 凭据读取或保存失败不阻止手动登录或成功跳转。

### 主动退出 Widget 测试

- 点击“退出登录”会调用仅删除密码的能力。
- 用户名仍保留。
- 即使删除密码失败，也会清除 token/user 并离开已登录页面。

### 认证过期回归测试

- 全局认证过期仍只清除 token/user。
- 认证过期链路不删除安全存储凭据。
- 进入带 `from` 的登录页后能够自动填充完整凭据。

## 非目标

- 不实现自动登录。
- 不实现“记住密码”开关。
- 不缓存注册页输入。
- 不修改登录请求字段、设备参数或签名逻辑。
- 不修改服务端 token 生命周期。
