# 影片网格默认详情导航设计

## 背景

`MovieGridView` 已经统一负责影片网格和 `MovieCard` 的构建，但影片点击行为目前由可选的 `onMovieTap` 参数决定。部分页面显式传入跳转详情页的回调，分类、搜索、公共列表和个人影片列表等页面没有传入，因此这些页面的影片卡片不可点击。

本次修改将详情导航收敛为 `MovieGridView` 的固定行为，让所有影片网格保持一致。

## 目标

- 点击任意 `MovieGridView` 中的影片卡片后打开该影片的详情页。
- 使用路由栈打开详情页，返回后保留来源页面的 Tab、筛选、分页数据和滚动位置。
- 删除旧有 `onMovieTap` API，避免调用方继续覆盖统一行为。
- 不改变独立使用 `MovieCard` 的页面或组件。

## 非目标

- 不修改影片详情页的数据加载或布局。
- 不修改 `MovieCard` 的通用点击回调能力。
- 不重构影片列表、分页或路由架构。
- 不处理当前工作区中与本功能无关的 Android 构建配置改动。

## 架构与组件变更

### `MovieGridView`

- 删除构造函数中的 `onMovieTap` 参数和对应字段。
- 引入 `go_router`。
- 在 `SliverGrid` 构建 `MovieCard` 时固定设置点击回调。
- 点击回调使用影片的 `id` 打开 `/movie/:id` 对应的详情页。

### 调用方

- 删除排行榜和演员详情等页面传给 `MovieGridView` 的 `onMovieTap`。
- 未传入回调的现有调用方无需修改，自动获得详情导航能力。
- 若调用方删除参数后不再使用 `go_router`，同步删除无用导入；仍有其他导航用途时保留。

## 数据与导航流程

1. 用户点击 `MovieGridView` 内的 `MovieCard`。
2. 网格读取当前 `MovieSummary.id`。
3. 网格通过 `context.push('/movie/${movie.id}')` 将详情页压入路由栈。
4. `AppRouter` 使用 `/movie/:id` 创建 `MovieDetailPage`。
5. 用户返回时弹出详情页，原网格页面及其状态继续保留。

这里使用 `push` 而不是 `go`，因为详情页是来源页面之上的临时层级，返回操作需要恢复原页面状态。

## 错误与边界处理

- `MovieSummary.id` 是现有详情接口和路由的必填标识，本次不新增空值或格式转换逻辑。
- 详情页请求失败继续由现有详情页错误状态处理。
- 本次不保留自定义点击回调；所有 `MovieGridView` 都必须进入影片详情页。

## 测试设计

### 共享组件测试

在 `movie_grid_view_test.dart` 中使用真实 `GoRouter`：

- 初始页面展示包含固定影片 ID 的 `MovieGridView`。
- 点击真实 `MovieCard`。
- 等待路由动画完成。
- 断言当前路由和详情测试页面对应 `/movie/<id>`。

该测试可捕获删除默认回调、使用错误影片 ID 或导航到错误路径等回归。

### 分类页回归测试

在分类页测试中使用可观察的详情路由：

- 加载分类页及真实 `MovieGridView`。
- 点击分类影片卡片。
- 断言进入对应影片详情路径。
- 返回后断言分类页和原 Tab 网格仍存在。

### 验证范围

- 先运行共享网格与分类页的定向测试。
- 运行全量 `flutter test`。
- 运行 `flutter analyze`。
- 运行格式化和差异检查。

## 兼容性

这是一次有意的内部 API 收敛。所有仓库内 `MovieGridView` 调用方将同时更新，因此不会保留已废弃参数或兼容分支。
