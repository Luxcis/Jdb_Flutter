# 设置页版本信息与 Token 认证设计

## 目标

在设置页所有设置 Cell 的最后增加当前版本展示，并提供一个五连击隐藏入口。用户可以通过该入口输入 Bearer Token；应用先使用候选 Token 获取当前用户信息，验证成功后再覆盖现有登录状态，使后续接口自动使用新 Token。

## 范围

本次包含：

- 在设置列表最后增加版本 Cell。
- 从实际安装包读取语义版本号。
- 连续点击版本 Cell 5 次后打开 Token 认证弹窗。
- 使用候选 Token 调用 `GET /api/v1/users` 获取用户信息。
- 验证成功后保存 Token 和用户信息，验证失败时保留原登录状态。
- 为 UI、认证状态和网络请求头行为增加回归测试。

本次不包含：

- 修改应用版本号。
- 展示构建号。
- 新增 Token 清除入口。
- 修改用户名密码登录流程。
- 修改服务端接口或 Token 格式。

## UI 与交互

### 版本 Cell

- 版本 Cell 必须位于设置页所有设置 Cell 的最后一行。
- 主标题固定为 `当前版本`。
- 副标题为实际安装包的语义版本号，例如 `0.7.1`。
- 不显示构建号，例如不显示 `+701`。
- 版本读取期间副标题使用稳定的占位状态，读取成功后替换为实际版本。
- 版本读取失败时页面仍可使用，副标题显示 `未知`。

### 五连击入口

- 点击目标为整个版本 Cell。
- 仅当从第一次点击起 2 秒内连续点击 5 次时打开认证弹窗。
- 从第一次点击起满 2 秒仍未达到 5 次时重新计数。
- 弹窗打开后立即清零计数，避免关闭弹窗后因旧计数再次触发。

### Token 认证弹窗

- 标题固定为 `认证 Token`。
- 提示固定为 `输入新的认证 Token 将覆盖当前登录信息。`。
- 提供单个 Token 输入框、`取消`按钮和`确定`按钮。
- 输入内容去除首尾空白后为空时不能提交。
- 提交期间显示加载状态，并禁用重复提交与关闭操作。
- Token 不写入日志、错误文本或测试快照。

## 版本信息来源

新增 `package_info_plus: ^8.3.1`，通过 `PackageInfo.fromPlatform()` 读取安装包版本，仅展示 `version` 字段。

选择 8.3.1 是为了兼容项目当前 Dart、Flutter 和 Android Gradle Plugin 基线。运行时读取可以保证展示值来自实际安装包，避免在 Dart 代码中重复维护版本常量。

## 认证架构

### 候选 Token 验证

候选 Token 在验证成功前不得写入 `AuthProvider` 或本地缓存。设置页通过专用认证服务发起：

```text
GET /api/v1/users
Authorization: Bearer <candidate-token>
```

该请求仍经过现有签名、响应解包、HTML 实体解码和域名切换链路，但使用请求级候选 Token 替代当前登录 Token。

候选 Token 验证失败属于弹窗内的输入错误，不得触发全局认证失效处理，不得清空当前登录状态，也不得跳转登录页。请求级认证覆盖和跳过全局认证失效的语义应封装在网络公共层，设置页面不直接操作 Dio 拦截器。

### 用户信息

以 `docs/main/api/jdb_api_openapi.json` 为准，`GET /api/v1/users` 成功响应经过 `ResponseInterceptor` 解包后应为 `UserEntity` 对象，真正的用户信息位于其非空 `user` 字段。只有 `user` 可转换为非空 `Map<String, dynamic>` 时才算验证成功；响应结构异常按验证失败处理。

### 原子覆盖

验证成功后调用现有 `AuthProvider.login(token: ..., user: ...)`，按现有契约同时更新：

- 内存中的 Token；
- 内存中的用户信息；
- `StorageKeys.token`；
- `StorageKeys.user`。

`AuthInterceptor` 每次请求都从 `AuthProvider` 动态读取 Token，因此覆盖完成后的其他接口会自动携带：

```text
Authorization: Bearer <new-token>
```

更新成功后关闭弹窗，并显示 `认证 Token 已更新`。

## 错误处理

- Token 为空：不发起请求，保持弹窗打开。
- Token 无效或服务端拒绝：保持弹窗打开并显示可读错误；原 Token 和用户信息不变。
- 网络错误：保持弹窗打开并允许重试；原登录状态不变。
- 用户响应结构异常：视为验证失败，不保存候选 Token。
- 本地持久化失败：显示保存失败，不能宣称更新成功。内存与缓存应保持一致，避免只更新一半。
- 版本读取失败：仅影响版本副标题，不能影响设置页和认证入口的其他功能。

## 组件边界

- `ProfileSettingsPage`：在现有 `cells` 列表最后追加版本 `ListTile`，并负责五连击计数、弹窗展示和提交状态。
- 版本信息加载器：封装安装包语义版本读取，便于 Widget 测试注入稳定值。
- Token 认证服务：使用候选 Token 请求 `/api/v1/users`，返回用户对象，不负责保存登录状态。
- `ApiClient` 与认证/响应拦截器：提供请求级候选 Token 和局部认证错误处理能力。
- `AuthProvider`：仍是 Token、用户信息和登录态的唯一持有者，验证成功后负责持久化。

## 测试策略

### Widget 测试

- `当前版本`位于设置 Cell 列表最后。
- 副标题只显示语义版本，例如 `0.7.1`，不显示 `+701`。
- 少于 5 次点击不打开弹窗。
- 2 秒内第 5 次点击打开弹窗。
- 超时后点击计数重新开始。
- 弹窗包含覆盖提示。
- 空 Token 不提交。
- 验证期间阻止重复提交。
- 验证失败时弹窗保留且原登录状态不变。
- 验证成功后关闭弹窗并显示成功提示。

### 单元与网络测试

- 候选 Token 请求使用新的 Bearer Token，而不是当前登录 Token。
- 候选 Token 验证失败不调用全局认证失效回调。
- `/api/v1/users` 成功响应转换为用户对象。
- 验证成功后 Token 与用户信息均持久化。
- 后续普通请求自动使用新 Token。

### 验证命令

- 运行设置页、认证 Provider 和网络拦截器相关的聚焦测试。
- 运行完整 `flutter test`。
- 运行 `flutter analyze`。
- 运行 `git diff --check`。

## 完成标准

- 设置页最后一行稳定显示主标题`当前版本`和实际语义版本副标题。
- 五连击能够打开认证弹窗，其他点击次数不会触发。
- 用户在提交前明确看到覆盖当前登录信息的提示。
- 只有 `/api/v1/users` 验证成功才覆盖并缓存 Token 与用户信息。
- 验证失败不会破坏原登录状态。
- 覆盖成功后的普通接口自动使用新 Token。
- 相关聚焦测试、完整测试和静态分析通过。
