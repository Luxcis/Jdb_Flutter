# 磁链搜索设计

## 目标

让首页“找磁链”豆腐块进入独立的磁链搜索流程：搜索首页展示独立历史和 startup 下发的近期磁链热词；提交后进入支持排序、分页加载和复制磁链的结果页。

## 范围

- 使用现有首页豆腐块路由 `/search/magnet`，不调整豆腐块尺寸、顺序或视觉。
- 磁链搜索历史与普通搜索历史完全隔离。
- 搜索结果使用 `/api/v1/search_magnet`，接口参数以用户提供的 OpenAPI 定义为准。
- 搜索结果列表与影片详情页磁链列表使用同一个共享列表项组件。
- 不新增第三方依赖，不修改普通搜索的业务行为。

## 路由与页面

### 磁链搜索首页

路由为 `/search/magnet`。页面结构和普通搜索首页一致：顶部搜索框，下方按顺序显示“历史搜索”和“近期热搜”。空模块不渲染。

- 手动提交：去除关键词首尾空白；空关键词不跳转；保存到独立磁链历史；进入结果页并标记 `from_recent=false`。
- 点击近期热搜：保存到独立磁链历史；进入结果页并标记 `from_recent=false`。
- 点击历史关键词：将该词移到历史首位；进入结果页并标记 `from_recent=true`。
- 清空操作只删除磁链搜索历史，不影响普通搜索历史。

### 磁链搜索结果页

路由为 `/search/magnet/results`，查询参数包含：

- `q`：去除首尾空白后的关键词，必填；为空时重定向到 `/search/magnet`。
- `from_recent`：仅历史关键词入口为 `true`，其他入口为 `false`。

结果页顶部保留可编辑搜索框。再次提交关键词时保存磁链历史，并以 `from_recent=false` 替换为新的结果路由。

搜索框下方提供四个单选排序项：

| 文案 | `sort_by` |
| --- | --- |
| 相关度 | `relevance` |
| 时间 | `created` |
| 文件数 | `files` |
| 文件大小 | `size` |

默认选中“相关度”。排序变化时保留关键词和 `from_recent`，清空旧分页数据并从第 1 页重新请求。

## startup 数据

`StartupData` 增加 `recentMagnetKeywords`，映射 JSON 字段 `recent_magnet_keywords`，缺失时为空列表。`StartupProvider` 在启动成功后保存不可变副本，并向磁链搜索首页提供该列表。

启动失败逻辑维持不变；近期磁链热词为空不影响启动成功。

## 独立历史缓存

新增缓存键 `key_magnet_search_history`。复用现有搜索历史存储规则，并允许历史存储指定缓存键：

- JSON 字符串数组；
- 去除关键词首尾空白；
- 去重并将最近使用项放在首位；
- 最多保留 20 条；
- 缓存损坏或包含非字符串项时按空历史处理。

普通搜索继续使用 `key_search_history`，磁链搜索使用 `key_magnet_search_history`。

## 网络与数据模型

新增磁链搜索数据源，调用 `GET /api/v1/search_magnet`。每次请求发送：

- `q`：当前关键词；
- `sort_by`：当前排序值；
- `from_recent`：字符串 `true` 或 `false`；
- `page`：从 1 开始；
- `limit`：固定为 48。

响应已由共享响应拦截器解包，数据源从 `magnets` 读取列表，从 `current_page` 读取当前页。列表项通过现有 `normalizeMagnetJson` 和 `Magnet.fromJson` 解析，兼容标题、hash、大小、文件数、创建日期、高清与字幕字段。

接口未定义总页数：当一页返回 48 条时推断可能存在下一页；少于 48 条时停止加载。该推断只控制客户端是否继续请求，不改变服务端返回的当前页。

## 共享磁链列表项

将影片详情页当前私有磁链项抽取为 `core/widgets` 下的共享组件，影片详情页和磁链结果页都直接使用该组件，避免视觉和交互漂移。

共享组件保留现有行为：

- 下载图标、标题、高清/字幕标签、文件数、大小和日期的布局与主题样式不变；
- hash 已是 `magnet:?` URI 时原样复制，否则补成 `magnet:?xt=urn:btih:<hash>`；
- 点击整项复制磁链到剪贴板；
- 成功后提示“磁力链接已复制”；
- 保留“复制磁力链接 ……”的无障碍按钮语义。

搜索结果使用与详情页相同的分隔线间距和颜色规则。

## 分页与页面状态

结果列表使用懒构建的单列列表。滚动接近底部时自动请求下一页，同一时间只允许一个分页请求。

- 首屏加载：居中显示加载指示器。
- 首屏失败：显示“磁链搜索失败”和重试操作。
- 空结果：显示“未找到相关磁链”。
- 追加加载：在列表底部显示小型加载指示器。
- 追加失败：保留已加载条目，在底部显示重试操作。
- 无更多数据：停止触发请求，不额外显示占位内容。
- 排序或关键词变化：作废旧请求结果，避免异步响应覆盖新查询。

## 文件边界

- `core/models`：继续使用现有 `Magnet`。
- `core/widgets`：承载共享磁链列表项，供详情页和搜索功能共同依赖。
- `features/search/models`：磁链排序枚举及其接口值。
- `features/search/services`：独立历史配置和磁链搜索数据源。
- `features/search/screens`：磁链搜索首页与结果页、分页页面状态。
- `core/models`、`core/providers`：承接 startup 近期磁链热词。
- `core/router`：注册磁链搜索结果子路由。

该边界保持 feature-first 规则：搜索功能不依赖影片详情 feature，两个 feature 只依赖 core 中的共享模型和组件。

## 测试与验收

### 单元测试

- `StartupData` 解析 `recent_magnet_keywords`，缺失时为空。
- `StartupProvider` 成功后暴露近期磁链热词。
- 普通搜索历史和磁链搜索历史互不影响。
- 磁链数据源发送完整参数，正确解析列表和当前页，并按 48 条规则推断下一页。
- 四个排序选项映射到正确的 `sort_by`。

### Widget 与路由测试

- 首页“找磁链”进入 `/search/magnet`。
- 磁链搜索首页展示独立历史和 startup 热词，支持清空。
- 手动、热词、历史三种入口分别产生正确的 `from_recent`。
- 空查询被拦截或重定向。
- 结果页默认排序正确，切换排序后从第 1 页刷新。
- 滚动到底部后请求 `page+1`，追加失败时保留现有列表并可重试。
- 点击结果项复制完整磁链并显示提示。
- 影片详情页与磁链结果页均使用共享磁链列表项，原有详情页行为不回归。
- 加载、错误、空结果和无更多数据状态符合设计。
