# 目标

检查更新结束后，在当前运行周期内记录检查结论：已检查到最新版时，设置页「检查更新」入口按钮变为「暂无更新」且不可点击；检查到新版本或检查失败时保持既有行为。检查状态不写入任何持久化存储，应用每次启动时重置为未检查。

# 范围

- 设置页（`ProfileSettingsScreen`）「当前版本」ListTile 中检查更新入口按钮的状态展示与可点击性。
- 会话级检查状态容器（profile 模块内、应用进程生命周期内的内存状态），不再落在 Screen State 上。
- 既有行为保持：有更新弹更新弹窗；无更新保留 SnackBar「已是最新版本」提示；失败保留 SnackBar「检查更新失败，请稍后重试」提示。

## Source coverage

无来源文档：需求由用户以文字直接提出，不进入源文档完整覆盖模式。

# 非目标

- 不改变更新弹窗、下载、哈希校验与安装触发行为（capability `in-app-update` 的其余部分不变）。
- 不持久化检查状态：不写 SharedPreferences、文件等任何持久存储。
- 不新增「启动时自动检查更新」等自动触发行为；检查仍仅在用户点击时发起。
- 不改变「当前版本」subtitle 的版本号展示与 5 连击隐藏入口的逻辑。

# 验收示例

- A1: 检查结果为已是最新版时，设置页入口按钮文案由「检查更新」变为「暂无更新」，且不可点击（onPressed 为 null）。
- A2: 检查结果为新版本时行为保持现状：弹出更新弹窗；弹窗关闭后入口按钮仍为「检查更新」且可再次触发检查。
- A3: 检查失败（网络异常/非 200/解析失败）时行为保持现状：按钮仍为「检查更新」且可再次触发，提示「检查更新失败，请稍后重试」不变。
- A4: 无更新时仍保留既有 SnackBar「已是最新版本」提示：本次只新增按钮状态，不删既有提示。
- A5: 检查结论的保持范围是整个应用运行周期：进入设置页检查确认「暂无更新」→ 返回并再次进入设置页，按钮仍为「暂无更新」且不可点击；不因离开页面而复位。
- A6: 检查状态不持久化：不向任何持久存储写入字段；应用重新启动后入口按钮恢复为「检查更新」可点击。

# 约束与不变量

- 检查状态只存于内存，生命周期为应用进程；进程启动即复位为初始「未检查」态。
- 不把检查状态放在 `ProfileSettingsScreen` 的 State 字段上：该页为 GoRoute 推入页面，State 随出入页面销毁重建，会导致同一次运行内状态过早复位（与「每次启动应用重置」不符）。
- 只记录结论状态：检查失败不改变按钮状态（无结论不占用记录）；结论被后续成功的检查覆盖更新。
- 文案与主题遵循项目规范：中文文案、Material 3，按钮禁用态仍走既有 `TextButton` 禁用样式；不新增依赖。
- `flutter analyze --no-pub` 零新增告警。

# 决策

- D1（Agent 推断，待用户最终确认复核）：「每次启动应用重置」唯一确定了状态复位时机是应用进程重启；同一次运行内进出设置页不复位。排除 Screen State 方案（每次重进设置页都会复位，与用户写明的复位时机不符）。状态采用会话级（进程级）内存容器。
- D2（Agent 决定）：无更新时保留既有 SnackBar「已是最新版本」提示，需求只要求新增按钮状态，不要求移除提示。
- D3（Agent 决定）：检查失败不记录任何结论并允许立即重试；「已检查最新版」的禁用态被下一次成功检查的新版本结论自然解除（恢复「检查更新」可点击，随即弹窗）。
- D4（Agent 决定）：状态容器实现为 profile 模块内的会话级 notifier（惰性初始化），Screen 监听其状态驱动按钮文案与可用性；容器注册/注入方式为实现细节，不进入正式规格。
- D5（Agent 决定）：capability 复用既有 `in-app-update`，在其上扩展「检查结论会话记忆」小节并更新完整规格。
