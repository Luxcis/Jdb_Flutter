# 目标

在线更新弹窗中，安装包下载完成后不再等待用户点击「安装」，自动触发安装流程：直接进入校验状态，计算已下载 APK 的 SHA-256 并与期望哈希比对，校验通过立即调起系统安装器；校验失败（不一致 / 无法校验）与调起失败按既有失败分支处理，恢复入口保持由用户手动触发。

# 范围

- 更新弹窗 `UpdateDialog`（`lib/features/profile/widgets/profile_update_dialog.dart`）：「下载完成 → 等待点击安装」的等待态被「下载完成 → 自动进入校验并调起安装」取代；弹窗内部状态机沿用 idle/downloading/downloaded/verifying，`downloaded` 仅保留为失败后的重试状态。
- 设置页编排 `_verifyAndInstallApk`（`lib/features/profile/screens/profile_settings_screen.dart`）：校验→调起安装器的编排逻辑不变，仅触发时机从点击变为下载完成后。
- 既有行为保持：期望哈希解析（digest 优先、同名 `.sha256` 文件回退）、mismatch 删除文件、无法校验 fail-closed 保留文件、校验中「正在校验安装包完整性…」展示与不可重复触发、通过后 `OpenFilex.open` 调起、非 done 结果降级提示。

# 非目标

- 不自动下载：APK 下载仍由用户在弹窗点击「立即更新」发起；新增「打开 App 自动检查/静默下载」皆不在范围内。
- 不改变哈希校验机制本身：算法、期望哈希来源与优先级、mismatch 与 unavailable 的区分、fail-closed 语义全部不变。
- 失败后不自动重验或自动重新下载：校验失败后的重新下载与重试安装仍由用户点击发起，避免失败时形成无人工介入的下载循环。
- 不改变下载实现：文件名与目录（`update/app-jade.apk`）、进度回调与展示、ABI 资产选择不变。
- 不改变检查更新入口、检查结论会话记忆、设置页其他行为。

# 验收示例

- A1: APK 下载完成且实际 SHA-256 与期望哈希一致时，弹窗自动进入校验状态并调起系统安装器，全程无需用户点击「安装」；调起成功（`OpenFilex` 返回 done）后弹窗关闭。
- A2: APK 下载完成的瞬间弹窗即展示「正在校验安装包完整性…」，安装编排（校验 + 调起）自动执行且仅执行一次：不存在「下载完成，点击『安装』可开始更新」的首次等待态，也不产生重复调用。
- A3: 自动校验结果为不一致时弹窗行为与既有分支一致：不调起安装器、删除已下载文件、提示「安装包校验失败，已阻止安装」，并保留「重新下载」入口；重新下载完成后再次自动进入校验流程。
- A4: 自动校验结果为无法校验（期望哈希缺失/非法、文件不可读）时弹窗 fail-closed：不调起安装器、保留已下载文件、提示「无法校验安装包完整性，已阻止安装」，并保留「安装」按钮供手动重试重验。
- A5: 校验通过但系统安装器调起失败时弹窗保持既有降级：提示「安装包已下载，请在通知栏/文件管理器中安装」，并保留「安装」按钮供手动重试调起。
- A6: 下载完成前弹窗行为不变：弹窗内容展示、下载进度（线性进度条 + 百分比）、下载失败的提示与重新下载入口均与现状一致。

# 约束与不变量

- fail-closed 不变：期望哈希无法确定（`digest` 缺失且 `.sha256` 不可用或格式非法）或本地文件不可读时，一律不调起安装器。
- 自动触发以弹窗仍挂载为前提：下载完成时若弹窗已关闭（`mounted == false`），不执行校验与调起，不引入关闭后静默安装。
- 校验中状态不可重复触发：自动路径只调用一次安装编排；失败态的「安装」按钮触发路径与既有点击路径一致。
- 失败恢复动作全部由用户手动触发：mismatch → 「重新下载」；unavailable/openFailed → 「安装」重试。自动流程在任一失败分支即停止，不再自动循环。
- 文案中文硬编码、Material 3；不新增依赖；校验与调起编排仍由 Screen 提供（`install` 回调结构不变）。

# 决策

- D1（Agent 推断，供最终确认复核）：「下载完成后自动触发安装流程」解读为——下载成功即直接沿用既有「校验 → 通过则调起安装器」流程，等待点击的完成态仅保留为失败后的重试态；自动触发不排除校验（校验是安装流程的一部分，先校验后调起）。失败后不自动重试：mismatch 会删除文件，若自动重新下载将形成无人工确认的反复下载循环；既有已验收行为即是以手动恢复为准，故失败分支保持不变。
- D2（Agent 决定）：下载完成时弹窗已关闭（用户在下载中已无法关闭弹窗，但极端时序下 unmounted）则放弃本次自动安装，文件保留在原路径；下一次检查更新重新下载时覆盖，不静默安装。
- D3（Agent 决定）：capability 复用既有 `in-app-update`，将其中「安装触发与哈希校验」一节改写为以自动触发为准的完整规格，其余小节不变；未使用 delta 关联（CLI 未生成关联草稿，与前置两个 update change 的做法一致）。
