# 目标

在搜索结果页顶部搜索框中修改关键词并提交后，应用按新关键词重新搜索并展示全新结果，而不是停留在旧关键词的结果上。关键词搜索结果页与磁链搜索结果页均需修复。

# 范围

- `lib/core/router/app_router.dart` 中 `/search/results` 与 `/search/magnet/results` 两个路由的页面键：将页面键扩展为包含完整 URI（含 query 参数），使关键词变化时页面被重建、各 Tab 以新关键词重新发起请求。
- 修复后页面重建带来的行为保持：AppBar 搜索框显示新关键词、返回键回到搜索首页、从结果页进入详情再返回时结果页状态保留。
- 为上述行为补充 widget 测试（注入 fake 数据源，验证提交新关键词后以新关键词重新拉取数据）。

# 非目标

- 不做输入过程中实时（边输边搜）搜索，仍以键盘搜索键提交触发。
- 不改动搜索历史保存逻辑。
- 不改动影片结果 Tab 的筛选条、磁链结果页的排序等其他已有功能。
- 不处理其他路由潜在的 pageKey 语义问题（如路径参数路由）。

# 验收示例

- A1: 在 `/search/results?q=旧词` 页面顶部搜索框修改为"新词"并提交键盘搜索键后，影片 Tab 按新词重新加载数据（fake 数据源收到 query="新词" 的请求），页面展示新词的结果。
- A2: 提交新关键词后，结果页 AppBar 搜索框中的文本为新关键词。
- A3: 在磁链搜索结果页顶部搜索框修改关键词并提交后，磁链列表按新关键词重新加载数据（fake 数据源收到 query="新词" 的请求），AppBar 搜索框文本为新关键词。
- A4: 在结果页提交仅含空白字符的关键词时，不发生导航、不重新搜索，停留在当前结果页。
- A5: 从搜索结果页进入影片详情后返回，结果页仍保留原关键词的结果与页面状态（页面未被意外重建）。
- A6: 在结果页提交新关键词后按系统返回，回到搜索首页（replace 语义不额外增加返回栈深度）。

# 约束与不变量

- 保持现有分页与跨 Tab 去重逻辑（`PaginationController`、`SearchPageSession`）不变；修复不得依赖对 `PaginationController` 的行为修改。
- 保持空关键词重定向行为：`/search/results` 无有效 `q` 时仍重定向回 `/search`；磁链路由同理。
- 保持路由跳转语义：结果页内重新搜索使用 replace 语义，不新增返回栈深度。
- 提交前确认 `pubspec.lock` 无非必要变更（本机 `flutter pub get` 会重写 lock 的源与版本）。

# 决策

- D1: 修复方式采用"页面键包含完整 URI（含 query）"（路由层一行级改动），而非在各 Tab State 中增加 `didUpdateWidget` 重新加载。理由：新搜索应得到全新结果页，与从搜索首页发起搜索的体验一致（回到影片 Tab、筛选与滚动重置）；改动集中，天然覆盖关键词变化与 `from_recent` 变化；避免在 7 个 Tab 与磁链页分散处理查询变化。
- D2: 重新搜索的触发方式维持提交触发（`TextInputAction.search` / `onSubmitted`），不做实时搜索。
- D3: 两个结果页提交机制不同（Build 阶段经 go_router 14.8.1 源码与探针验证）：关键词结果页用 `context.replace`（parser.dart 保留原页面键 → 页面 State 保留 → 真正的 bug 来源）；磁链结果页用 `context.pushReplacement`（parser.dart 每次生成唯一页面键 → 页面本就重建重搜，修复前已具备该能力）。磁链页同样改为完整 URI 页面键，仅作为一致性与回归防护，不改变其可见行为。
- D4: 关键词结果页提交相同关键词时 URI 不变、页面键不变，页面状态保留、不重新请求（replace 语义视为无操作）；磁链结果页提交相同关键词会重建并重新请求（pushReplacement 语义，修复前既已如此，保持不变）。
