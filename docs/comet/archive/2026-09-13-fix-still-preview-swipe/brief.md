# 目标

修复影片详情页「预告片 / 剧照」区剧照预览的滑动异常：长剧照列表向左滑动后无法再向右滑动，向右滑动时列表闪回（突然跳回开头）。要求横向滚动在任意方向、任意长度下保持稳定。

# 范围

- 现状：`MovieScreenshotSection` 横向列表中的 `MovieStillThumbnail`（自适应宽高比）为 StatefulWidget，宽高比状态仅保存在组件内部。
- 根因（Agent 调查，可复现机制）：横向 `ListView` 滑出 `cacheExtent` 的缩略图 State 被销毁；用户向左滑远后向右滑回时，重新挂载的缩略图先以 16:9 占位宽度布局，图片解码回调（`ImageSizeListener` 异步）到达后才再次改变宽度。回滑过程中列表项宽度不断变化，滚动位置被 Flutter 持续修正，表现为闪烁、跳回列表开头，且手势中的滚动被抵消，无法继续向右滑动。这是 `detail-still-autoscale` 引入宽度自适应后的回归。
- 修改目标：缩略图宽高比按 URL 记忆（模块级缓存或等价机制），重新挂载时同步使用已记忆的比例，消除回滑时的二次宽度变化与滚动修正。
- 涉及文件：`lib/core/widgets/movie_still_thumbnail.dart`（主体）；必要时配套测试。

# 非目标

- 不改变点击打开 `ImageGalleryViewer`、语义标签、Key 与占位/clamp 行为本身。
- 不改变全屏大图查看器 `ImageGalleryViewer`、预告片封面缩略图、其他 `CachedImage` 使用方。
- 不改变 `CachedImage` / `JdbImageCacheManager` 的加载、缓存、解密与模糊逻辑。
- 不重写 `MovieScreenshotSection` 列表结构（不引入 SliverList 静态布局改造），以最小修复使现有懒构建列表滚动稳定。

# 验收示例

- A1: 剧照图片都已加载并展示后，将长剧照列表向左滑动远离起点，再向右滑动可正常回滑，不出现闪回（跳回列表开头）或滚动被抵消。
- A2: 缩略图滚出可见区域后再滚回，立即以与之前加载完成时相同的宽高比显示，不再经历「16:9 占位 → 实际比例」的二次宽度变化。
- A3: 保留原有行为：加载前 16:9 占位、加载完成后按实际宽高比完整显示、竖图/超宽图 clamp [1.0, 21/9]、点击与语义不变。
- A4: 同一 URL 的宽高比记忆在整段会话内有效，同一张剧照在两次滚回时宽度一致。

# 约束与不变量

- 区块整体高度 164、横向列表懒构建结构与区块高度不变。
- 剧照缩略图保留 `Semantics`（button、label「查看剧照 N，共 M 张」）与 `movie-detail-screenshot-N` Key。
- 遵循项目规则：Material 3、无本地化（中文硬编码）、无触觉反馈改动。

# 决策

- D1（Agent 决定，根因定位）：症状为 `MovieStillThumbnail` State 重新挂载叠加异步图片尺寸回调，横向懒构建列表在回滑时出现宽度二次变化导致的滚动偏移修正。修复方案为「按 URL 记忆宽高比，重挂载时同步复原」。
- D2（Agent 决定，实现方式）：宽高比记忆为只增不改的模块级缓存（key 为缩略图传入的 URL，同一图片比例恒定）；缓存无淘汰策略，生命周期随进程。属于实现细节，不产生其他可观察行为。
- D3（Agent 决定）：若真机验证发现滚动仍在极端情况下抖动，允许追加稳健性实现（如保证宽度在首次布局前确定），但不得突破非目标边界。
