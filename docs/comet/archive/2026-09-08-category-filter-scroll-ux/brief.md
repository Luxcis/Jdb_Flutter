# 目标

优化类别页（有码/无码/欧美/FC2/动漫）的筛选体验：

1. 切换筛选条件（标签、排序方式、升降序）触发影片网格自动刷新时，影片网格自动滚动回顶部，让用户立即看到新筛选结果的开头。
2. 底部筛选面板（CategoryFilterSheet）记录筛选列表的滚动位置，收起后再次展开时恢复到收起前的位置。

# 范围

- 影响页面：类别页 `CategoriesPage`（`lib/features/categories/screens/categories_screen.dart`）。
- 影响组件：
  - `MovieGridView`（`lib/core/widgets/movie_grid_view.dart`）：新增可选能力（外部 ScrollController + 刷新时滚动置顶开关），默认行为不变，其他复用页面（首页、榜单、搜索、关注、个人资料等 12+ 处）不受影响。
  - `CategoryFilterSheet` / `_FilterBody`（`lib/features/categories/widgets/category_filter_sheet.dart`）：筛选列表 ListView 接受外部 ScrollController。
  - 类别页 State：按 Tab 持有影片网格与筛选列表的 ScrollController 并管理其生命周期。
- 滚动位置记忆的生命周期：页面内存内保留（页面未销毁期间，打开-收起-再打开恢复）；不跨应用重启持久化。
- 每个 Tab 的筛选面板滚动位置独立记忆（各 Tab 筛选项不同）。

# 非目标

- 不改变其他页面复用 `MovieGridView` 的滚动行为（置顶能力为 opt-in，默认关闭）。
- 不改变下拉刷新、加载更多、错误重试的现有行为。
- 不改变筛选条件即时生效（自动刷新、保留旧数据直到新数据到达）的现有逻辑。
- 不改变“切换 Tab 时影片网格滚动位置独立保留”的既有行为（有既有测试保护）。
- 不做筛选面板滚动位置的跨会话持久化。

# 验收示例

- A1: 类别页影片网格已向下滚动到非零偏移后，打开筛选面板点选任一标签触发自动刷新，当前 Tab 影片网格滚动偏移回到 0。
- A2: 类别页影片网格已向下滚动到非零偏移后，在筛选面板切换排序方式或发布日期升降序，当前 Tab 影片网格滚动偏移回到 0。
- A3: 筛选触发的滚动置顶只作用于当前 Tab 的网格：Tab 0 网格滚动到非零偏移、Tab 1 网格滚动到另一非零偏移后，在 Tab 0 变更筛选条件触发刷新，Tab 0 网格偏移回到 0，切到 Tab 1 后其网格偏移保持不变（“切换 Tab 网格滚动位置独立保留”的既有行为不回归）。
- A4: 筛选面板内筛选列表已向下滚动到非零偏移后收起面板，再次展开时筛选列表滚动偏移恢复到收起前的值。
- A5: 各 Tab 的筛选面板滚动位置相互独立：Tab 0 筛选列表滚动到偏移 X 后收起，切到 Tab 1 展开筛选并将列表滚动到偏移 Y 后收起，再切回 Tab 0 展开，筛选列表恢复偏移 X。

# 约束与不变量

- 筛选触发刷新沿用“保留旧数据直到新数据到达”的现有策略（`preserveItems: true`）不变。
- 滚动置顶在触发刷新的同一时机（帧末）执行，不等待网络结果；不得在 build 期间直接修改滚动位置。
- ScrollController 生命周期由持有方管理，页面销毁时释放，不得泄漏。
- 现有测试全部继续通过；新增行为有对应 widget 测试覆盖。

# 决策

- D1: “切换筛选条件”包含标签选择、排序方式、发布日期升降序三类筛选面板内会触发自动刷新的操作，三者刷新后网格都置顶。理由：同一机制、同一用户预期（内容重排后顶部才是新结果的开头）。
- D2: 滚动置顶采用瞬时跳转（滚动偏移直接归零），在触发刷新的帧末执行。理由：实现可靠、语义直接；数据替换前用户注意力在筛选面板上，无感知跳动。
- D3: 筛选面板滚动位置通过类别页 State 按 Tab 持有 ScrollController 实现，不使用 PageStorage 或持久化存储。理由：需求只要求开合之间保持；模态路由的 PageStorage 不可靠，持久化属过度设计。
- D4: `MovieGridView` 的置顶能力做成可选参数（默认关闭），仅类别页开启。理由：该组件被 12+ 页面复用，须避免改变其他页面行为。
