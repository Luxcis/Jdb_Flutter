# 目标

重构预告片播放页（MoviePreviewScreen）的播放操作层：放弃 media_kit 内置的 `MaterialVideoControls`，改为项目自管理的自定义操作层，让顶部标题栏与底部操作栏由同一个显隐状态机驱动、同步显示隐藏，并补齐四类手势能力——长按 2 倍速播放、屏幕左半区垂直滑动调节屏幕亮度、右半区垂直滑动调节系统音量（调节时实时展示当前亮度/音量）、水平滑动快进快退。

# 范围

- `lib/features/movie_detail/services/movie_preview_playback.dart`：`buildView()` 改用 `NoVideoControls`（不再使用 media_kit 内置控制层）；`MoviePreviewPlayback` 接口扩展倍速设置能力（如 `setRate`）。
- `lib/features/movie_detail/screens/movie_preview_screen.dart`：播放态页面叠加自定义操作层；进入播放后操作层默认可见并按时自动隐藏。
- 新增操作层组件（`lib/features/movie_detail/widgets/`）：统一显隐状态机驱动的顶部标题栏 + 底部操作栏（播放/暂停按钮、进度条、当前位置/时长）、以及倍速/亮度/音量/快进退指示器。
- 新增手势处理：单击切换操作层显隐；双击播放/暂停（保留现有行为）；长按 2 倍速、松开恢复原速；左半区垂直滑调节亮度；右半区垂直滑调节音量；水平滑按拖动距离快进快退。
- 新增屏幕亮度与系统音量的服务抽象（可注入、可测试），接入系统通道实现真实调节。
- 更新与新增单元/组件测试，覆盖显隐状态机与四类手势。

# 非目标

- 不修改设备全局状态层：`MoviePreviewOperationManager`、方向锁定、wakelock、系统栏沉浸（既有 `movie-preview-operations` 规格）保持不变。
- 不修改预告片视频源、路由配置、详情页入口 UI。
- 不引入双击快进/快退（双击统一保留为播放/暂停）。
- 不涉及画中画、字幕、清晰度切换、横竖屏切换按钮、下载等业务。
- 不修改 `MoviePreviewHeader` 的既有结构（返回按钮 + 标题），只改变其显隐驱动方式。

# 验收示例

- **A1**. 播放页面中，顶部标题栏与底部操作栏始终同步显示、同步隐藏：单击播放画面可在“两者同时显示”与“两者同时隐藏”之间切换，不存在只显示其一的状态。
- **A2**. 操作层显示后，在持续播放且无交互约 3 秒后自动同时隐藏；暂停、缓冲、播放完成或出错时操作层保持显示，不自动隐藏。
- **A3**. 播放中长按画面任意位置，播放速度变为 2 倍并显示倍速指示；松开手指后立即恢复 1 倍原速，倍速指示消失。
- **A4**. 在屏幕左半区上下滑动时，屏幕亮度随之增大/减小，并实时显示当前亮度（图标 + 百分比）；手指离开后继续滑动可连续调节。
- **A5**. 在屏幕右半区上下滑动时，系统媒体音量随之增大/减小，并实时显示当前音量（图标 + 百分比）；手指离开后继续滑动可连续调节。
- **A6**. 在播放画面上左右滑动时，按拖动距离快进/快退，滑动过程中实时显示目标位置（或偏移量）；松开后播放停留在目标位置。
- **A7**. 双击播放画面仍在“播放 ↔ 暂停”之间切换（与现有行为一致），且不再触发 media_kit 内置的双击快退/快进。
- **A8**. 加载中与播放失败页面保持现有行为：顶部标题栏可见可返回，不显示底部操作栏与手势指示器。
- **A9**. 全部 `test/features/movie_detail/movie_preview_*` 测试与新增操作层测试通过；`dart analyze` 无错误。

# 约束与不变量

- **单一显隐来源**：顶部标题栏与底部操作栏的可见性必须由同一个状态（同一计时器/通知器）驱动，禁止各自维护独立计时器。
- **手势判定互斥**：同一触摸序列只触发一类手势（单击/双击/长按/垂直滑/水平滑），以首段位移方向判定滑动类型；垂直滑与水平滑不得在一次触摸中先后触发。
- **边缘避让**：手势热区避开屏幕边缘安全距离（参考 media_kit 的 16dp 边界），避免与系统返回手势冲突。
- **亮度恢复**：屏幕亮度调节仅作用于本页面会话，退出播放页时恢复进入前的系统亮度；系统音量调节为系统级生效，退出后不回退。
- **倍速恢复**：倍速仅存在长按期间；页面切换、播放完成、出错或会话清理时不得残留 2 倍速状态。
- **构造兼容**：保持现有测试注入方式（`playbackFactory`、协调器注入等）可用，新增依赖（亮度/音量服务）同样可注入 fake。
- **失败隔离**：亮度/音量通道调用失败只记录日志，不影响播放与操作层显隐。

# 决策

- 放弃 media_kit 内置 `MaterialVideoControls` 改自定义操作层：其控件显隐状态不对外公开，无法满足“顶部标题栏与底部操作栏同步显隐”；亮度/音量回调也需自行提供。长按倍速、垂直滑、水平滑随之统一由自研手势层实现。
- 底部操作栏保留播放/暂停按钮、进度条、当前位置与时长；去掉全屏按钮（页面已强制横屏）与 media_kit 其余用不到的按钮。
- 单击切换显隐与双击播放/暂停共存：单击延时判定（约 300ms 双击窗口），与现有 `MoviePreviewDoubleTapDetector` 的判定窗口一致。
- 亮度/音量通过新增可注入服务抽象接入系统通道（如 `screen_brightness` / `volume_controller` 或等价实现），测试以 fake 验证调节数值。
- 左半区=亮度、右半区=音量，与主流播放器及 media_kit 默认布局一致。
- 水平滑动全程（满宽拖动）映射固定 seek 窗口（参考主流播放器约 90 秒量级），按实际拖动距离比例换算目标位置并 clamp 在 `[0, duration]`。
