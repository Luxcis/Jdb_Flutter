# Capability: in-app-update（应用内在线更新）

本能力描述应用内更新的完整行为：检查更新、检查结论的会话记忆、下载安装包、安装触发与安装包哈希校验。功能仅面向 Android。主题与文案遵循项目 RULES（中文硬编码、Material 3）。

## 检查更新（既有行为）

- 检查入口位于「我的-设置」页；使用 `SettingsProvider.githubProxy` 作为 GitHub 代理前缀。
- `UpdateChecker.check()` 请求 `https://api.github.com/repos/Luxcis/Jdb_Flutter/releases/latest`（按代理规则拼接），解析 `tag_name`、`body` 与 `assets`（含 `digest`）。
- 版本比较使用语义化版本（pub_semver）：latest > current 视为有更新；否则视为已是最新版；解析失败不视为有更新。

### Scenario: 更新检查行为保持不变

Given 用户在设置页触发检查更新
When GitHub latest release 的版本与本机版本比较完成
Then 有更新时弹出更新弹窗；无更新或请求或解析失败时保持既有提示行为，提示与提示文案进入路径不变

## 检查结论的会话记忆（本次新增）

- 每次成功检查（拿到无更新或有更新结论）后，将结论记录在应用进程内的会话级内存状态中；该状态由设置页「当前版本」ListTile 的入口按钮消费，驱动按钮的文案与可点击性。
- 结论为“已是最新版”时：入口按钮文案变为「暂无更新」，按钮进入禁用态（不可点击）。
- 结论为“有更新”时：入口按钮保持「检查更新」可点击，检查与弹窗流程与此前一致，不因记录而改变。
- 检查失败（网络异常、非 200、解析失败）不产生结论：按钮保持「检查更新」可点击，允许立即重试。
- 同一次应用运行内，结论跨设置页离开/重入保持不变（不放在页面 State 上）；下一次成功检查得到的新结论覆盖旧结论。
- 会话状态不持久化：不写 SharedPreferences、文件等任何持久存储，只在内存中存活。
- 应用进程重新启动后，状态回到「未检查」初始态：入口按钮恢复「检查更新」且可点击。
- 用户隐式重检的情形：状态为「暂无更新」时按钮已禁用，用户无法在本次运行内再次触发检查；重启应用即恢复检查能力。
- 检查入口仍为用户手动触发，不新增启动时自动检查。

### Scenario: 无更新结论使入口变为暂无更新且禁用

Given 用户在设置页触发检查更新且 GitHub latest release 版本不高于本机版本
When 检查返回无更新结论
Then 入口按钮文案变为「暂无更新」且进入禁用态不可点击，仍保留既有 SnackBar「已是最新版本」提示

### Scenario: 有更新结论保持既有弹窗与按钮

Given 用户在设置页触发检查更新且 GitHub latest release 版本高于本机版本
When 检查返回有更新结论
Then 弹出更新弹窗（既有流程），入口按钮仍为「检查更新」且可再次触发检查

### Scenario: 检查失败不改变入口状态

Given 用户在设置页触发检查更新
When 请求失败（网络异常、非 200 或解析失败）
Then 入口按钮保持「检查更新」且可立即重试，提示「检查更新失败，请稍后重试」不变，不记录任何结论

### Scenario: 同一运行内重进设置页保留检查结论

Given 本次应用运行内已检查出「无更新」结论
When 用户离开设置页后再次进入设置页
Then 入口按钮仍为「暂无更新」且不可点击，不因页面重建而复位

### Scenario: 状态不持久化且应用重启后复位

Given 任何时刻应用运行内记录过检查结论
When 应用进程重启后进入设置页
Then 入口按钮恢复「检查更新」且可点击；整个功能不向任何持久存储写入状态

## 资产选择与下载（既有行为）

- `UpdateInstaller.pickAsset` 按设备 `supportedAbis` 顺序匹配资产名，无匹配时回退第一个资产。
- 下载流式写入 `<应用文档目录>/update/app-jade.apk`，进度通过回调 `(received, total)` 上报，弹窗以线性进度条与百分比展示；固定文件名与目录不变。

### Scenario: 下载与进度展示保持不变

Given 用户在更新弹窗点击「立即更新」
When APK 正在下载
Then 展示线性进度与百分比，进度回调的行为与目录、固定文件名保持现状；下载失败时弹窗提示失败且可重新下载

## 安装触发与哈希校验（update-apk-hash-verify 引入）

- 下载完成后弹窗进入待安装状态：显示「安装」按钮；用户未点击前不调起系统安装器。
- 点击「安装」时计算已下载 APK 的实际 SHA-256（package:crypto），与期望哈希比对后通过才调起 `OpenFilex` 打开系统安装器。
- 期望哈希优先取 release JSON 中资产自带的 `digest` 字段（`sha256:<hex>`）；缺失时回退下载同名 `<asset名>.sha256` 文件（`sha256sum` 输出格式），取首列哈希为期望值。
- 比对忽略 `sha256:` 前缀与十六进制大小写；期望值缺失、下载失败或格式非法（非 64 位十六进制）一律视为「无法校验」。
- 校验期间弹窗显示「正在校验安装包完整性…」，同一时刻不可重复触发。
- 校验不一致：不调起安装器，删除已下载文件，弹窗提示「安装包校验失败，已阻止安装」，允许重新下载。
- 无法校验（fail-closed）：不调起安装器，保留已下载文件，弹窗提示「无法校验安装包完整性，已阻止安装」，允许重试。

### Scenario: 下载完成显示安装入口

Given APK 已下载完成
When 更新弹窗绘制
Then 弹窗处于完成态并展示「安装」按钮，系统安装器未被调起

### Scenario: 校验通过后调起系统安装器

Given 已下载 APK 的实际 SHA-256 与期望哈希一致（期望值来自 `digest` 或 `.sha256` 文件均可）
When 用户点击「安装」
Then 先完成校验再通过 `OpenFilex` 调起系统安装器，弹窗不出现校验失败提示

### Scenario: 校验不一致阻止安装并删除文件

Given 已下载 APK 的实际 SHA-256 与期望哈希不一致
When 用户点击「安装」并完成校验
Then 不调起系统安装器，删除已下载文件，弹窗提示「安装包校验失败，已阻止安装」并允许重新下载

### Scenario: digest 缺失回退 .sha256 文件校验

Given 资产 `digest` 字段缺失且同名 `.sha256` 文件可下载
When 用户点击「安装」
Then 以该文件解析出的期望哈希（首列哈希、忽略 `sha256:` 前缀与十六进制大小写）与实际 SHA-256 比对，校验结果行为与使用 `digest` 时一致

### Scenario: 期望哈希不可用时阻止安装

Given 资产 `digest` 缺失、`.sha256` 文件下载失败或期望值格式非法
When 用户点击「安装」
Then 不调起系统安装器，弹窗提示「无法校验安装包完整性，已阻止安装」，保留已下载文件并允许重试；不静默跳过校验直接安装

### Scenario: 校验过程状态展示

Given 校验正在执行
When 更新弹窗绘制
Then 显示「正在校验安装包完整性…」状态且不可重复触发；校验结束后仅有通过（调起安装器）或失败（对应失败提示）两种可见结果

## 打开系统安装器（既有行为）

- 校验通过后经 `OpenFilex.open` 调起；返回非 done 结果时提示「安装包已下载，请在通知栏/文件管理器中安装」。

### Scenario: 调起失败提示保持不变

Given 校验通过且已调用 `OpenFilex.open`
When 返回结果类型不是 done
Then 保持既有降级提示「安装包已下载，请在通知栏/文件管理器中安装」，不因本次改动变化
